# Статистика: две UX-концепции

Поручение от 20.10.2026. Самостоятельный HTML/CSS/JS-макет раздела, без sidebar и оболочки приложения. Не изменяет React, API, схему или общие токены. Все названия и показатели демонстрационные. Оба варианта доступны через переключатель над разделом.

## Что решает каждый вариант

**А — рекомендуемое направление для сценария заказчика «быстро оценить сеть и найти проблемы».** Сводка показывает взвешенный процент и объём данных. Рядом со сравнением — незакрытые журналы и филиалы с низкой посещаемостью. На телефоне проблемы идут раньше полного сравнения. Переход из проблемы открывает отобранные строки варианта Б; раскрытие филиала показывает группы и все дополнительные показатели.

**Б — для подробного сравнения.** Вместо многослойных подписей внутри каждой ячейки — одна строка на филиал или группу. Присутствия, пропуски, план и открытые журналы сравниваются по колонкам. Поиск, сортировка и отбор по проблеме сокращают список. Причины пропусков и группы скрыты до раскрытия. На телефоне вместо горизонтальной таблицы — компактный список со всеми показателями и отдельной сортировкой.

В обоих вариантах: быстрые периоды, произвольные включительные даты, филиал и группа, явный применённый контекст, группа выбирает свой филиал, смена филиала сбрасывает группу. Период и контекст сохраняются при переключении А/Б, обновлении и переходе из проблемы к сравнению. Ввод дат применяется отдельно; неверный диапазон не меняет отчёт. «Сегодня» фиксировано на 20.10.2026, «Неделя» — 19–20.10.2026. Ручной диапазон между быстрыми пресетами отдельно не запоминается: это ограничение макета, не предложение менять действующий контракт приложения.

## Посещаемость и финансы

Предложение, **не утверждённое изменение требований**: сейчас оставить одну предметную область без пустой вкладки «Финансы». Финансы отложены в действующем [PRODUCT.md](../../../PRODUCT.md). Когда финансовая отчётность появится, разделение внутри «Статистики» логично: у областей разные метрики, детализация и действия. Общими могут быть период и филиал. Смешанный обзор оправдан при наличии связанных данных и конкретного сценария владельца.

## Сохраняем достоверность

- Посещаемость — `present / (present + absent)` только по закрытым занятиям. Общий процент взвешен по отметкам. Присутствия не названы уникальными спортсменами.
- Закрытые пустые занятия учитываются в числе проведённых; отсутствие отметок даёт «—», а не 0%. Филиал без отметок остаётся в сравнении.
- Отменённые исключены; план и открытые журналы отдельно. Все три причины сохранены, их сумма равна пропускам.
- Контрольный месяц: 237 закрытых, 3 713 присутствий, 933 пропуска, 79,9%; 40 запланированных и 6 открытых. Причины: 462 болезнь, 226 уважительная, 245 неизвестна. Итоги филиалов и групп согласованы; дневной расклад синтетический.
- «Ниже 80%» — явно обозначенный ориентир макета, **не норматив PRIDE**. В production следует отдельно подтвердить необходимость и значение порога.
- Нет выдуманных приростов, уникальных спортсменов, прогнозов оттока, временных графиков или неподтверждённых финансовых данных. Текущий контракт агрегированного API не содержит этих показателей.
- Переход к открытым журналам отбирает филиалы. Экран самого журнала вне этого макета; раскрытие поясняет ограничение.

## Проверка и ограничения

Проверены обе композиции в Chromium на 1280, 390 и текущей узкой панели 319 px. Два ограниченных раунда визуальной проверки; на телефоне уплотнены итоги и подняты проблемы. При 319 px ширина документа равна доступной ширине; desktop-таблица исключена из мобильного отображения. При 390 px все видимые интерактивные цели не меньше 44 × 44 px. Есть клавиатурный фокус, подписи полей/иконок, `aria-expanded`, `aria-sort`, live-сообщения, уменьшенная анимация, состояния empty/error/retry/loading. Пустой поиск, пустой период и ошибка доступны через интерфейс, два последних — также через «Проверить состояния прототипа» внизу.

В браузере пройдены: раскрытие филиала → группа → правильный контекст; сброс группы при смене филиала; филиал без отметок; отбор 2 филиалов ниже порога / 3 с открытыми журналами; сортировка; поиск без совпадений / 2 группы Минска; неверный диапазон дат; пустой период; ошибка/повтор; сохранение фильтров при обновлении; быстрые даты. Суммы таблицы совпали с итогом сети. Ошибок JavaScript в браузере нет. `node --check statistics.js` прошёл.

Impeccable detector выполнен один раз: `[]`, **degraded regex**, без модулей HTML/CSS-парсера; вычисленный контраст этим инструментом не проверен. Проверка не объявляется полной сертификацией доступности. Реальные мобильные устройства, Safari и подключение API вне задачи. Скриншоты проверки хранятся в локальном `.impeccable/review/statistics/`.

Это исследовательская работа по прямому поручению, отдельный от feature-issues макет. Существующие issues реализации не занимались, production-код не изменялся. Следующий шаг — выбрать композицию, затем отдельным поручением подготовить issue переноса в React с действующими правами/контрактом данных. Существующие очереди разработки этот прототип не резервирует.
