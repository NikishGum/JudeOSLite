# Сотрудники — два UX-варианта

20.10.2026. Локальные HTML/CSS/JS-концепции по прямому поручению заказчика, без оболочки приложения. Заказчик выбрал вариант Б «Карточка доступа» для переноса в основное приложение; А сохранён как рассмотренная альтернатива. Исходный React/API не изменены.

Из корня репозитория:

```sh
python3 -m http.server 4187 --bind 127.0.0.1
```

- [А — быстрый реестр](http://127.0.0.1:4187/design-system/prototypes/staff/?concept=a): единый список, роли с филиалами и состояние доступа. Клик по имени открывает карточку с операциями.
- [Б — карточка доступа](http://127.0.0.1:4187/design-system/prototypes/staff/?concept=b): список и выбранный аккаунт рядом; на телефоне карточка заменяет список с кнопкой возврата. Предпочтительный вариант для частого изменения доступа.

В обоих один реестр сотрудников: тренер и администратор — совмещаемые роли, а не разные категории людей. По уточнению заказчика от 20.10 удалены вкладки «Все сотрудники / Тренеры филиала». Фильтры роли и филиала проверяют одно конкретное назначение, а не случайные роли в разных филиалах.

Работают поиск, сортировка, фильтры роли/филиала/доступа, создание мокового аккаунта, назначение существующего сотрудника, редактирование имени/логина, демонстрация смены пароля, снятие одного назначения, отключение/включение всего аккаунта. После перезагрузки изменения сбрасываются. Данные синтетические; пароль не сохраняется в объекте аккаунта, localStorage или на сервере. Для проверки вводить только вымышленные значения.

Текущие токены и локальный Rubik подключены напрямую из design-system. Зелёный и янтарный — существующие рекомендации Working Panel из frontend/src/app/app.css, не новые цвета источника PRIDE.

Прототип демонстрирует возможности владельца. В production необходимо сохранить серверные ограничения администратора и owner-only операции из docs/trainers-v1.md. Объединённая выдача trainer/admin-роли в одной форме — предложение UX, а не утверждение о готовом едином API.

Следующий шаг: перенос выбранного Б в основное приложение и необходимые дополнения backend по [issue #215](https://github.com/NikishGum/JudeOSLite/issues/215). Выбор подтверждён заказчиком 20.10.2026. [Решение и границы](../../../docs/staff-access-redesign.md). Прототип не является готовой production-реализацией.
