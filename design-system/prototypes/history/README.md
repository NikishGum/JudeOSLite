# История — два UX-концепта

Локальный HTML/CSS/JS-прототип по запросу заказчика от 20.10.2026. Сам раздел,
без навигации и оболочки приложения. Оба варианта — предложения для сравнения;
выбранного решения и поручения переносить его в React пока нет.

Из корня этого рабочего каталога:

```sh
python3 -m http.server 8767 --bind 127.0.0.1
```

- [А · Компактный журнал](http://127.0.0.1:8767/design-system/prototypes/history/index.html?view=journal)
- [Б · Лента по дням](http://127.0.0.1:8767/design-system/prototypes/history/index.html?view=feed)

Альтернатива — открыть `index.html` напрямую. Сборка и зависимости не нужны;
шрифт и токены подключаются из существующего `design-system/`.

## Разница подходов

**А — поиск и сверка.** Табличные строки вместо больших карточек. Время, действие,
запись и сотрудник сопоставляются по колонкам; технические сведения раскрываются
внутри строки. На телефоне та же последовательность становится компактным списком.

**Б — обзор последовательности.** Дни отделены друг от друга, события сформулированы
как действия. Последовательные отметки одного автора и филиала в пределах пяти
минут сворачиваются в группу; каждая запись доступна при раскрытии. Группировка
не утверждает, что события относятся к одному занятию: session ID в публичном аудите
сейчас нет. Дата в заголовке группы считается по загруженной части списка.

Оба варианта: поиск, фильтр филиала, быстрые периоды, произвольные даты, действие,
сотрудник, сброс, дозагрузка, раскрытие ID, загрузка, пустой результат и ошибка
с повтором. Фильтры применяются сразу. Переключатель концептов — только средство
сравнения, не предложение добавить его в приложение.

## Граница прототипа

Все 28 событий, имена и идентификаторы вымышлены; дата примера фиксирована:
20 октября 2026, Europe/Minsk. По умолчанию семь дней включают 26 событий.
Используется только публичный набор полей существующей истории: время, автор,
филиал, действие, тип и ID записи. Private payload, контакты и причины коррекций
не показываются. Читаемое действие — форматирование известного action;
неизвестное значение сохраняет честное «Другое действие».

Поиск и фильтр сотрудника сейчас работают по локальному массиву. Для реального
приложения потребуется серверный поиск/фильтр либо честная маркировка поиска
только по загруженным событиям. Количество здесь известно из полного мокового
набора; текущий API с keyset-пагинацией не возвращает общий total. Не переносить
этот счётчик как реальный без контракта API. В рабочем приложении сохранить
ролевой доступ, newest-first, курсор и размер страницы сервера.

Никакие React-компоненты, API, права и глобальные токены не изменены.

## Проверка

Браузерные проверки 20.10.2026: оба варианта при 1280 и 390 px, дополнительно
отсутствие горизонтального переполнения при 320 px. Проверены поиск по сотруднику,
филиал, действие и сотрудник вместе, произвольный период/ошибка порядка дат,
пустой результат, Enter-раскрытие, дозагрузка, ошибка и повторная загрузка.
У видимых полей и кнопок высота не ниже 44 px. Локальный Rubik и исходные цвета
проверены. Это проверка прототипа, не сквозной тест production и не полная проверка
со скринридером или физическими телефонами.

Impeccable detector: один запуск, regex fallback без замечаний; HTML parser modules
недоступны, поэтому полноценную проверку каскада/контраста он не выполнял.
Снимки и независимое заключение — `.impeccable/review/history/` в рабочем каталоге.
