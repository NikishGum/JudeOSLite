## Рабочее место

На ПК — компактный список (действующие/архив/все) и выбранная группа справа;
ниже1100px — список → группа → «К списку групп». Имя/филиал и читаемая сводка
правил остаются над вкладками «Состав» и «Расписание». Учитываются все действующие
интервалы; дополнительные интервалы видны в полной сводке. Будущие версии подписаны
«С …», а действующая версия не скрывается за будущей. Название группы не используется

После создания доступны независимые добавление участников и настройка расписания;
оба шага можно отложить. Выбранная вкладка, дата состава и начало периода хранятся
в памяти компонента по groupId при переключении/возврате. detail ID остаётся в

подтверждённый уход размонтирует форму, без персональных черновиков в storage.

## Состав

«Состав на дату» — исторический просмотр `[from,until)`. «Дата зачисления» и
«Дата действия» — независимые даты записи. Реестр с поиском/пагинацией позволяет
выбрать несколько карточек, в том числе на разных страницах. Перед сохранением
видны имена, группа, дата и число выбранных.

Добавления — **отдельные команды**, не атомарный batch. UI прямо предупреждает
об этом и показывает поимённый исход каждой команды. Успешные карточки исключаются
из повторной отправки; при отказе остаются выбранными. Двойной submit блокируется,
весь проход учитывается существующим pending lifecycle. Потерянный ответ сверяется
с историей по groupId/from/until; если перечитать её нельзя, результат «неизвестен»,
повтор заблокирован до проверки. При размонтировании следующие команды не отправляются.
Новый endpoint/миграция для этого не нужны.

Из строки состава доступны перевод, завершение и датированная история участника.
До подтверждения указаны последний день в прежней и первый день в новой группе.
Действуют прежние версии/проверки периодов/архивов/прав и снимки занятий.
Массовый перевод рассмотрен и оставлен за пределами реализации: сохранён атомарный
перевод одного участника, множественный выбор относится к добавлению.

## Расписание и исключения

Один источник — прежние `/schedule` и `/sessions`. Новый локальный редактор
GroupScheduleEditor фиксирует clubId/groupId; сохраняет weekly/day_parity/date_list,
датированное изменение серии и реальный previewToken с affected/preserved.
Разовое занятие — самостоятельное действие через неизменённый SessionForm.
После сохранения правила/сводки/даты перечитываются и вызывается trainingChanged().

Сначала правила (дни/тип, время окончания, тренер, `[from,until)`, timezone),
затем только28 дней выбранной группы. Период можно сдвинуть или задать его начало.
Пустые даты, отсутствие правил и ошибка загрузки различаются. Нет спортсменов,
отметок или межгруппового календаря. Операции отдельного занятия находятся в меню:
перенос будущего planned без freeze, отмена planned/open, допустимая замена тренера.
Контекст формы показывает группу, исходные фактические дату/время и тренера.
Дальний перенос/разовое занятие переводит список на новую дату после успешного save.

Отмена требует причины и отдельного confirmOpen для открытого журнала. Запись остаётся
cancelled с причиной; snapshot/marks/history сохраняются, автоматических пропусков нет,
статистика исключает cancelled. Closed не получает действий отмены/переноса/замены.
Все ограничения повторно проверяются сервером, stale response сохраняет ввод и
требует перечитывания. sourceDate показывает исходное вхождение перенесённого занятия;
это не прежнее время. Даты используют сохранённую timezone, а не timezone браузера.

**Раздел «Занятия» не меняется:** ни UI/маршруты/навигация, ни SessionForm,
ScheduleEditor, CSS/токены, API или семантика backend. Из группы сохранён прежний
переход «К занятиям группы». Изменяются только серверные данные существующих сущностей,
которые естественно появляются в обзоре. События уведомлений обслуживает действующий
backend; новая интеграция SMS/email/push не вводится, отправка не обещается.
