# RD-04: статистика владельца и история

Реализация [#186](https://github.com/NikishGum/JudeOSLite/issues/186), 14.10.2026.
Визуальная основа — [Working Panel](../design-system/prototypes/dashboard/DESIGN.md),
[PRIDE](../DESIGN.md), существующая оболочка RD-01. Режим Impeccable: Operate.
Статический прототип не изменяется. API, SQL, права и миграции v1 сохранены.

## Периоды и контекст

Начальный диапазон: первое число текущего месяца — сегодня. Кнопки вычисляют
реальную дату **Europe/Minsk** в момент нажатия: Сегодня — один день; Неделя —
понедельник текущей недели по сегодня; Месяц — первое число по сегодня.
Обе границы включены. Неделя может начинаться в прошлом месяце/году.
Браузерный часовой пояс не меняет эти определения. Это календарные фильтры,
а не пересчёт времён занятий: API продолжает определять день начала каждого
занятия в **его сохранённом timezone**, включая историческое смещение UTC.

Редактирование любой даты переключает «Свой период». Последний ручной диапазон
сохраняется в памяти компонента при переключении быстрых периодов и возвращается
кнопкой «Свой период»; refresh/retry/выбор филиала/группы не меняют его.
После размонтирования/reload начальный диапазон снова текущий месяц.
В URL/history/storage нет персональных данных, черновиков или кеша итогов.

Филиал отчёта явно отделён от рабочего филиала в верхней панели. Начальный
отчёт — вся сеть, независимо от шапки; собственный заголовок показывает его
реальные выбранные филиал/группу. Кнопка строки сравнения выбирает **clubId/groupId**,
не название. Выбор сетевой группы одновременно выбирает её филиал; смена филиала
сбрасывает группу. Группы с одинаковыми названиями подписаны филиалами.
Исторические архивные филиалы/группы и пустые закрытые занятия остаются видимы.

«Занятия выбранного контекста» использует готовый `sessionHref` RD-03:
`/clubs/:clubId/sessions?group=:groupId&from=:from&through=:until&view=period`.
Это обычная ссылка с reload/back и серверной проверкой scope, включая
модифицированный клик/новую вкладку. Шапка календаря выбирает соответствующий
рабочий филиал, группа и обе даты видимы в календаре. Архивному филиалу ссылка
не предлагается; архивный отчёт не открывает создание будущих занятий.
App/router/shared/API/токены не изменяются.

## Read-only контракт для RD-05

- `features/owner-dashboard/types.ts`: `ReportSelection` — `from`, `until`,
  `clubId`, `groupId`; существующие `Report`, `Row`, `Totals`, `Filters`.
- `useAttendanceReport(selection)` возвращает `report | null`, `filters | null`,
  `loading`, `error`, `refresh`. Он делает авторизованные GET reports/filters и
  reports/attendance; не выводит итог из DOM или частичной страницы.
- `AttendanceReport({ report, onSelect? })` — полоса четырёх итогов, planned/open,
  все три причины, сравнения и объяснение расчёта.
- `ReportComparison({ rows, groups?, onSelect? })` — отдельное сравнение;
  callback получает `{ clubId, groupId }`. Без callback представление только читает.
- `reportPeriod('today' | 'week' | 'month')` — единое определение быстрых дат.

RD-05 владеет отдельным состоянием фильтров главной и использует эти экспорты;
не нужно дублировать формулу, endpoint или проценты. Вызывающая приватная область
должна иметь такую же границу user/owner/назначений, как NavigationBoundary RD-01.
Не следует одновременно монтировать скрытый отчёт и главную ради фонового кеша.

Сервер считает present/(present+absent) только по closed, без cancelled;
planned/open отдельно. UI только форматирует серверный процент до 0,1%.
Нулевой знаменатель — «—»; нулевые счётчики остаются нулями. Причины суммируются
в absent. Ошибка не подменяется нулями. Ключ текущего запроса запрещает показывать
предыдущие итоги ещё до cleanup эффекта; AbortController исключает поздний ответ.
Refresh скрывает прежний итог на время чтения. Событие `attendance-changed`,
возврат фокуса/видимости и 30 секунд в видимом окне перечитывают сервер.

На ПК — единая полоса метрик и таблицы. Незавершённые, отметки и причины
сгруппированы в подписанные ячейки, все поля v1 сохранены. На телефоне — полоса
2×2 и список с каждым показателем; скрытая desktop-таблица не входит в accessibility tree.

## История

Существующий публичный envelope: время, имя сотрудника/disabled, филиал/archive,
вид записи, entityId и действие. ID раскрывается по «ID записи». Raw payload,
контакты, логины и причины коррекций не выводятся и не запрашиваются отдельно.
Время и границы дат — Europe/Minsk, имена актуальные на момент чтения.

Владелец выбирает сеть, отдельный доступный/архивный филиал либо «Сеть · без филиала»;
администратор — только выданные сервером назначения; trainer-only раздел не получает.
Даты/действие/филиал применяются кнопкой либо Enter в date input. Над результатом
показаны **применённые** фильтры, отличные от ещё не применённого ввода.
Это read-only фильтры, не форма предметного черновика: переход не вызывает ложный
диалог о несохранённых данных.

Стабильная серверная keyset-пагинация `(created_at, id)` сохранена: новые сверху,
до 50 событий на страницу, cursor привязан к фильтрам. Следующая/предыдущая
страницы используют стек курсоров; новый фильтр/«Обновить историю» возвращают первую
страницу. Обычное фоновое обновление перечитывает текущую страницу. Не обещается
замороженный снимок всех страниц; более новые вставки видны после обновления первой.
Abort/epoch, очистка до запроса и граница назначений исключают старый scope.
Есть loading/empty/error/retry; attendance-changed также обновляет историю.
