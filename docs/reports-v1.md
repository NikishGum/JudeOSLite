# Статистика владельца V1-12

12.10.2026, [#160](https://github.com/NikishGum/JudeOSLite/issues/160). Владелец видит сеть, выбирает филиал/группу/период и сравнивает филиалы и группы. Администратору и тренеру отчёт и его справочники недоступны, в том числе при нескольких назначениях. Архивные филиалы и группы доступны для исторического чтения.

## API и вычисления

- `GET /api/reports/filters` → `{clubs: [{id,name,archived}], groups: [{id,clubId,name,archived}]}`. Названия актуальные; идентичность группы — UUID вместе с филиалом, одинаковые названия не объединяются. Контактов/участников/объяснений исправлений нет.
- `GET /api/reports/attendance?from=YYYY-MM-DD&until=YYYY-MM-DD&clubId=UUID&groupId=UUID` → `{from,until,total,clubs,groups}`. Обе даты обязательны, **включительны**, 0001–9999; `from ≤ until`. Необязательные пустые clubId/groupId означают всю сеть/все группы. Группу можно выбрать по сети; вместе с филиалом она должна ему принадлежать. Неизвестные/повторные параметры и неверные даты/UUID дают 400; отсутствующий ID или несовместимые клуб/группа — 404.
- `total` и строки сравнения содержат `closed,planned,open,present,absent,unknown,illness,excused,percentage`. Строка дополнительно содержит clubId/clubName/clubArchived и groupId/groupName/groupArchived; для итогов филиала groupId/groupName — null. Пустые списки `[]`, пустые счётчики 0, `percentage` при нулевом знаменателе **null**.

Дата периода — `(training_sessions.starts_at AT TIME ZONE training_sessions.timezone)::date`, по **сохранённой зоне и фактическому времени** занятия, без sourceDate/starts_on и без даты закрытия/правки. Историческая зона может иметь иной UTC-offset, чем сегодня; например Europe/Minsk в феврале 2000 года UTC+02. До/после границ исключено; начало и конец включены, даже если UTC-дата отличается.

Одна SQL-выборка сначала агрегирует attendance_records на сеанс, затем `GROUPING SETS` вычисляет сеть/филиалы/группы в одном MVCC-снимке. Так closed с пустым составом даёт одно проведённое занятие, несколько отметок не умножают число занятий, а конкурентная коррекция/закрытие не создаёт разные итоги сравнения и сети. `cancelled` и `superseded_at IS NOT NULL` исключены независимо от сохранённых отметок. `planned` и `open` считаются отдельно; их отметки не входят в суммы/процент.

`percentage = present × 100 / (present + absent)` по **текущим исправленным отметкам closed**. SQL возвращает дробное значение без округления; UI округляет только отображение до одного десятичного знака (0,1 процентного пункта), десятичная запятая. Нет отметок → «—», даже при проведённых пустых занятиях. Причины unknown/illness/excused суммируются в absent. Сетевой процент вычисляется по суммарным отметкам, не средним процентам филиалов.

Источник истории — сохранённые club_id/group_id сеанса и frozen attendance_records; текущий состав/карточки и audit не участвуют в суммах. Перевод/архив не перемещает прежние отметки. Группы/филиалы без занятий также показаны с нулевыми счётчиками. Новых таблиц, миграций, сохранённых итогов, кеша или materialized views нет.

Перед каждым чтением `auth.Require` и повторный `auth.LockSession` внутри транзакции проверяют живой аккаунт/is_owner/сессию под shared locks. Отзыв после middleware запрещает выдачу. 401 без входа, 403 без owner или после отзыва, 503 при недоступности; безопасные сообщения и `Cache-Control: no-store`. Отчёт только читает, аудит не создаёт.

## Интерфейс

Обновление 14.10.2026: RD-04 заменяет прежнюю композицию ниже на Working Panel,
быстрые даты/возврат ручного диапазона, полный мобильный список и переход по ID.
Актуальный [UI/read-only контракт](redesign-reports.md) и [проверка](redesign-reports-validation.md).
Расчёт и API этого документа не меняются. Описание прокручиваемых таблиц на телефоне
ниже относится к предыдущей v1: сейчас телефон получает подписанный список.

«Статистика владельца» доступна после входа без выбора рабочего филиала. Собственные фильтры отчёта независимы от филиала реестра/журналов. Начальный период — с первого числа текущего месяца по сегодня Europe/Minsk. Смена филиала сбрасывает группу; сетевой список групп обозначает филиал и архив. Итоги, причины и две таблицы сравнения; на телефоне таблицы прокручиваются внутри доступной с клавиатуры области, страница не переполняется.

После успешной коррекции через AdminJournal в том же окне событие `attendance-changed` сразу перечитывает SQL-итоги. Из другого окна — явная кнопка обновления, возврат фокуса либо 30 секунд в видимом окне. Ошибка/новый фильтр скрывают прежние итоги; retry сохраняет фильтры. AbortController запрещает позднему ответу прежнего фильтра вернуть старый результат. Выход/смена аккаунта/утрата owner очищают компонент; локальное хранилище и офлайн-очередь не используются.
