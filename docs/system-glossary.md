# Люди, роли и сущности PRIDE

Словарь текущей системы, 19.10.2026. Основа — `main` `358d03e`, исполняемые
миграции0001–0013, действующие API и [контракты новых модулей](backend-contracts/README.md).
Переименование подтверждено заказчиком в этом чате: раздел «Клиенты» называется
**«Семьи и родители»**, спортсмен в платежах — **«Участник»**.

## Люди и роли

| Термин | Что обозначает |
| --- | --- |
| Участник / спортсмен | Человек, который занимается в клубе. ФИО и дата рождения образуют общую карточку человека (`participants`). Сам по себе участник не получает логин и права сотрудника. |
| Ребёнок | Название того же участника в семейном кабинете. Дополнительная карточка человека не создаётся. Связь с семьёй задаётся явно. |
| Родитель / представитель | Пользователь, которому явно выдан доступ к семье. Читает данные связанных детей; доступ не определяется совпадением фамилии или телефона. Это прикладная роль доступа, а не проверка юридического родства. |
| Сотрудник | Пользователь с правами владельца, администратора или тренера. Это общий термин для работников клуба, а не ещё одна роль с собственными правами. |
| Владелец | Пользователь с правами управления сетью филиалов (`staff_users.is_owner`). |
| Администратор | Сотрудник, назначенный в конкретные филиалы. В пределах разрешённых филиалов управляет реестром, семьями, группами, занятиями, журналами и ручными финансами. |
| Тренер | Сотрудник с назначением тренера в филиале и назначениями на конкретные занятия. Ведёт свои журналы; семейные контакты и финансовый журнал ему не открываются. |
| Контактное лицо | Имя и телефон/email, указанные для семьи или карточки участника в филиале. Наличие контакта не создаёт аккаунт и не выдаёт доступ. |
| Плательщик | Реальный человек, который передал деньги. Отдельной карточки плательщика сейчас нет: финансовая запись относится к участнику в филиале, а создавший запись сотрудник хранится отдельно. |

Один аккаунт может одновременно иметь несколько независимых ролей: например,
администратор филиала А, тренер филиала Б и родитель в своей семье.
Отзыв семейного доступа сохраняет независимые роли сотрудника.

## Организация, реестр и семья

| Термин | Что обозначает | Хранение / связь |
| --- | --- | --- |
| Клуб / сеть PRIDE | Организация, для которой работает CRM; объединяет филиалы. Отдельная карточка сети или юридического лица сейчас не создаётся. | Контекст приложения |
| Филиал | Отдельный зал: название, адрес, часовой пояс и архивное состояние. Основная граница данных и назначений. | `clubs` |
| Карточка участника в филиале | Запись человека в конкретном филиале: дата вступления, местные контакты, архив. Именно к ней относятся группа, семья, оплаты и посещения. Один человек и его запись в филиале — разные уровни данных. | `club_memberships` → `participants` + `clubs` |
| Семья | Явно объединённые карточки детей одного филиала, общие контакты и список аккаунтов с доступом. Один membership может состоять только в одной семье. Семья не является логином. | `families` |
| Состав семьи | Связь семьи с карточками участников этого же филиала. | `family_children` |
| Родительский аккаунт | Обычная учётная запись человека, связанная с одной или несколькими семьями. В семье может быть несколько таких аккаунтов. | `staff_users` + `family_access` |
| Доступ к семье | Явное разрешение конкретному аккаунту видеть конкретную семью и связанных детей. Удаление связи отзывает последующие чтения. | `family_access` |

Пример: Анна входит под одним родительским аккаунтом. В филиале «Центральный»
есть одна семья Ивановых и два участника — Максим и София. Семья объединяет их
карточки, а посещения и оплаты считаются отдельно для каждого участника.

## Группы, занятия и посещаемость

| Термин | Что обозначает | Хранение / связь |
| --- | --- | --- |
| Группа | Именованная группа внутри филиала. Тренер конкретного занятия задаётся в расписании или самом занятии. | `training_groups` |
| Состав группы | Участие карточки спортсмена в группе на интервале дат. История сохраняется при переводе или исключении; в один день у карточки не бывает двух действующих групп. | `group_memberships` |
| Правило расписания | Шаблон занятий: группа, тренер, время, длительность, часовой пояс, период действия и способ выбора дат. Есть дни недели, чётность дат и список дат. | `schedule_rules` |
| Версия / серия расписания | Датированные варианты одного расписания. Изменение правила не переписывает уже состоявшиеся занятия. | `schedule_rules.series_id` + интервалы |
| Разовое занятие | Конкретное занятие, созданное без повторяющегося правила. | `training_sessions` без `schedule_rule_id` |
| Занятие | Конкретная тренировка с датой, временем, группой и фактическим тренером. Состояния: запланировано, журнал открыт, завершено, отменено. | `training_sessions` |
| Назначение тренера на занятие | Указание, кто фактически ведёт именно эту тренировку. При замене меняется назначенный тренер занятия; это не новая учётная запись. | `training_sessions.trainer_id` |
| Журнал | Представление одного занятия и его зафиксированного состава с отметками. Отдельной таблицы журналов нет. | Занятие + `attendance_records` |
| Снимок состава | Участники, зафиксированные при открытии журнала по составу группы на дату занятия. Последующие переводы и архивирование не переписывают этот состав. | Ключи `attendance_records` |
| Отметка посещения | Одна строка участника в конкретном журнале: ещё не отмечен, присутствовал либо отсутствовал с причиной. | `attendance_records` |
| Причина отсутствия | Значение отметки: неизвестна, болезнь или уважительная причина. Это не отдельный человек, документ или группа. | `attendance_records.absence_reason` |
| Коррекция посещения | Исправление отметки закрытого журнала администратором/владельцем с обязательной причиной. История сохраняется; число использованных занятий абонемента пересчитывается при чтении. | Отметка + `audit_events` |

## Оплаты и абонементы

| Термин | Что обозначает | Хранение / связь |
| --- | --- | --- |
| Тариф | Шаблон предложения филиала: название, цена в BYN, количество занятий и срок в днях. | `billing_plans` |
| Финансовая запись / платёж | Запись суммы и назначения для конкретного участника в филиале. Содержит состояние, способ ручной оплаты, дату и историю изменений. | `payments` |
| Счёт | Та же финансовая запись до подтверждения получения денег: `pending`. Отдельной сущности/таблицы счетов нет. | `payments.status = pending` |
| Подтверждённая оплата | Финансовая запись с полученной суммой, способом и датой оплаты: `paid`. | `payments.status = paid` |
| Аннулированная запись | Счёт или оплата, отменённые с причиной: `void`. Аннулирование записи само по себе не выполняет банковский возврат. | `payments.status = void` |
| Абонемент | Индивидуальный пакет занятий участника по конкретному счёту/оплате; ожидает подтверждения оплаты перед активацией. Хранит копию условий тарифа, даты действия и число использованных занятий. Изменение тарифа не меняет старый абонемент. | `subscriptions` → `payments` |
| Использованное занятие | Присутствие в закрытом журнале внутри срока абонемента. Отменённые и открытые занятия не расходуют лимит. Это расчёт, а не отдельная платёжная запись. | Вычисляется по посещаемости |
| Способ оплаты | Наличные, карта, перевод или ЕРИП, вручную отмеченные сотрудником. Отдельной карточки банка или платёжного оператора нет. | `payments.method` |
| Финансовая сводка | Расчёт сумм и количества подтверждённых оплат/ожидающих счетов и сумм по месяцам. | Результат запроса к `payments` |

**Тариф и абонемент различаются:** «12 занятий за 30 дней» — тариф;
абонемент Максима с определёнными датами и использованными посещениями — экземпляр
для участника. **Счёт и оплата различаются состоянием одной записи.**

Реальный iPay сейчас не подключён. ЕРИП в ручной записи не означает получение
подтверждения от платёжного шлюза. Частичные оплаты, авансы, старые долги и
автоматические возвраты не входят в текущую реализацию.

## Доступ, история и служебные данные

| Термин | Что обозначает | Хранение / связь |
| --- | --- | --- |
| Аккаунт / учётная запись | Логин, отображаемое имя, пароль в защищённом виде и состояние доступа человека. Общая идентичность сотрудников и родителей. | `staff_users` |
| Назначение в филиал | Разрешение аккаунту быть администратором или тренером конкретного филиала. Роль родителя выдаётся семейной связью, а не этим назначением. | `staff_club_roles` |
| Сессия входа | Временный вход аккаунта в браузере/приложении, который может истечь или быть отозван. Отличается от тренировочного занятия, хотя в коде оба используют слово session. | `staff_sessions` |
| Событие истории / аудит | Запись, кто, когда и какую сущность изменил; с допустимыми состояниями до/после и причиной. История не является второй копией реестра. | `audit_events` |
| Профиль пользователя | Экран текущего аккаунта и его ролей. Это представление данных аккаунта. | Отдельная сущность не создаётся |
| Кабинет родителя | Ограниченное рабочее пространство аккаунта с семейным доступом. | Семьи, участники и разрешённые записи |
| Статистика / отчёт | Результат расчёта по существующим данным. Посещаемость считается по закрытым занятиям; отменённые исключены. | Отдельная сущность не создаётся |
| Архив | Состояние филиала, карточки участника, группы или тарифа, сохраняющее историю. Архивирование не создаёт нового человека или отдельное хранилище. | Поля соответствующих записей |
| Миграция БД | Техническая версия структуры БД и её контрольная сумма. К людям и предметным объектам клуба не относится. | `public.schema_migrations` |

В исполняемой схеме0001–0013 —19 предметных/служебных таблиц в `pride` и таблица
версий миграций в `public`. Часть терминов выше описывает роль, связь, состояние
или представление, поэтому отдельной таблицы для каждого слова нет.

## Термин «клиент»

Отдельного предметного объекта «клиент» в текущей модели нет. Прежнее название
раздела относилось к семьям, а подпись в платежах — к участнику. Во избежание
двух смыслов используем «Семьи и родители» для семейного раздела и «Участник»
для спортсмена, в том числе в формах оплаты. Названия URL/API (`families`,
`participants`, `membershipId`) при уточнении интерфейсных подписей сохраняются.

В технических документах «клиент API» означает frontend или программу, которая
обращается к серверу; это технический термин, а не карточка человека в клубе.
