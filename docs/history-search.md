# История: компактный журнал и поиск

UX-HISTORY / [#220](https://github.com/NikishGum/JudeOSLite/issues/220), 21.10.2026.
Утверждён вариант А, референс `ddee243a2d698328dbbff38bf29250f18b69f960`.
Композиция переносится в существующий PRIDE/shadcn; оболочка и права сохраняются.
Этот документ заменяет прежнюю форму/постраничные кнопки истории из RD-04.

## Памятка сотруднику

Откройте «История». По умолчанию показаны последние семь календарных дней,
включая сегодня, по Europe/Minsk. Филиал из начального контекста приложения
сохраняется; владелец может выбрать всю сеть или «Сеть · без филиала»,
администратор — «Все мои филиалы» либо один разрешённый филиал. Архивные филиалы
доступны для чтения и явно подписаны.

Введите имя, название/код действия, тип записи или полный/короткий ID.
Все слова должны встречаться в событии, порядок не важен: «Калиновская исправлена»
и «исправлена Калиновская» дают один результат. Поиск по подстроке, без морфологии;
регистр и е/ё не различаются. Начальный # у ID допускается. Поиск работает по всей
разрешённой истории, включая ещё не загруженные события. Enter применяет сразу,
обычный ввод — через300ms; Escape и крестик очищают только запрос.

Периоды: сегодня, вчера, семь дней, всё время, произвольные даты. Обе даты
включительны. Неверный/неполный диапазон не отправляется: результат остаётся по
предыдущим применённым датам, указанным над таблицей. «Фильтры» раскрывает действие
и сотрудника. Условия применяются сразу; после закрытия панели остаются отдельные
кнопки снятия условий. Одноимённые авторы различаются по UUID/короткому ID,
отключённые аккаунты остаются доступны в истории. После удаления условия фокус
возвращается к соответствующему полю либо кнопке «Фильтры».

Время, действие, тип/короткий ID и сотрудник/филиал образуют компактную строку.
На телефоне это линейный список. Кнопка подробностей раскрывает секунды, полный
ID события/записи/автора и технические коды. Сокращённый ID служит подсказкой,
ключ записи — полный UUID. Имена и названия актуальны на момент чтения.

«Загружено N из M» различает объём чтения и общее число совпадений. «Показать ещё»
использует серверный курсор, «Обновить» начинает с начала с прежними условиями.
«Сбросить всё» возвращает всю разрешённую область и текущие семь дней.
Пустой поиск можно очистить, сохранив точные условия, либо раскрыть фильтры.

## Публичный API

Существующие пути и поля сохранены, новые поля добавлены:

- `GET /api/audit/filters`: `isOwner`, `clubs`, `actions`, **`actors`**
  (`id`, `name`, `disabled`), **`actionLabels`**, **`entityLabels`**.
- `GET /api/audit/events`: прежние `clubId`, `action`, `from`, `until`, `cursor`,
  новые **`q`**, **`actorId`**. Ответ: `items`, `nextCursor`, **`total`**.
- Публичный event envelope прежний: UUID/time, actorId/name/disabled,
  clubId/name/archived, entityType/entityId/action; добавлены `actionLabel`,
  `entityLabel`. До/после, контакты, логины, пароли и причины коррекций отсутствуют.

`q` ограничен160 Unicode code points до нормализации. Невалидный UTF-8,
управляющие символы кроме whitespace, повторные/неизвестные параметры,
неверные UUID/даты/курсоры дают400. Пустые прежние параметры совместимы.
`actorId` — UUID, никогда имя. Чужой/несуществующий UUID даёт одинаковый пустой
результат в разрешённом scope; глобального lookup аккаунтов нет.

Нормализация: lowercase, ё→е, разделение Unicode whitespace, удаление одного
начального # у каждого слова. Все непустые слова соединяются через AND по
подстрокам общей публичной поисковой строки: автор, филиал (или сеть без филиала),
название/код/явные алиасы действия и типа, полный ID записи и события. `%`, `_`,
кавычки и backslash буквальны: SQL использует `strpos`, не LIKE/динамический SQL.
Имена/значения передаются параметрами. Морфологии и языка запросов нет.

Словарь `backend/internal/audit/catalog.go` — единственный источник подписей и
явных поисковых алиасов (`corrected` включает «исправлена»). Он же используется
SQL, filters metadata и event labels; frontend не содержит второго словаря.
Неизвестный код показывается и ищется буквально, остаётся точным action-фильтром.

Авторы выбираются DISTINCT по UUID **только из разрешённых audit_events**,
независимо от текущих ролей автора/disabled. Одноимённые люди не объединяются.
Варианты отражают всю разрешённую историю, не только текущие дату/действие/поиск;
это позволяет вернуться к прежнему сотруднику, не теряя выбранные условия.

## Права, снимок чтения и пагинация

Каждый endpoint заново проверяет живую сессию/роль и удерживает существующие
actor/session/administrator блокировки. Owner читает сеть, включая NULL club_id;
admin — только назначенные филиалы (включая архивные); trainer/parent-only403.
Список авторов, action options, поиск и total используют тот же SQL scope.
Чужие аккаунты/события/наличие совпадений не перечисляются. Все ответы no-store.

Один SQL statement с `matched AS MATERIALIZED` формирует публичные строки и
count **до** keyset-ограничения. Поэтому `items` и `total` относятся к одному
MVCC snapshot, в том числе при пустой странице после удаления событий.
Полный total считается по тем же scope/club/action/dates/actor/search.
Он может измениться при следующем запросе: снимок всей серии страниц не обещается.
Новые события перед курсором попадут в список после чтения с начала; total
последнего ответа уже учитывает их. Не выводить total из загруженной страницы.

Сортировка `(created_at DESC, id DESC)`, размер50 и lookahead51 сохранены.
Fingerprint включает canonical club/action/dates, actor UUID и нормализованные
отсортированные слова. Другое условие отклоняет курсор400; прежний fingerprint
сохранён для запросов без новых условий, поэтому старые курсоры продолжают работать.

Фоновый focus/visibility/attendance-changed/30s перечитывает загруженный объём
с начала, сохраняя row identity, раскрытые подробности и введённые даты.
Обновление публикуется только после успешного чтения всего этого объёма.
Транспортная ошибка сохраняет показанные строки и даёт retry;401/403/404/410
скрывает данные. Filter/query changes отменяют запрос, очищают прежний результат
и сбрасывают cursor; AbortController+epoch исключают поздние ответы. Navigation
boundary и существующий session generation защищают logout/смену пользователя/ролей.

Индексы/миграции не добавлены: точный count всё равно требует проверки всех
совпадений. Используются существующие scope/time индексы; нет отдельного поиска,
триграммного индекса без измеренной необходимости или новых ролей.
