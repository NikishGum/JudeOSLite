# Расписание V1-07

12.10.2026, [#155](https://github.com/NikishGum/JudeOSLite/issues/155). Владелец/администратор выбирает действующую группу, тренера своего филиала, локальное время и длительность. Четыре отдельных режима: дни недели (ISO 1–7), чётность **числа дня месяца**, конечный список дат календаря и разовое занятие без правила. Чётность остаётся инженерным допущением от 12.10.2026.

## Даты и генерация

Миграция 0007 добавляет schedule_rules и training_sessions; прежние миграции/таблицы/ID не меняются. Составные FK согласуют club/group/rule; исторические trainer_id ссылаются на staff_users, не на удаляемое назначение. Никаких финансов, отметок или отдельной системы назначений групп.

Даты строгие YYYY-MM-DD, время HH:mm, длительность 1–1440 минут. Регулярный период `[from,until)`, null конец открыт. Для date_list — до 1000 уникальных выбранных дат, без until; все даты создаются сразу, в том числе за горизонтом. once требует одну будущую дату и не создаёт schedule_rules. Начало регулярного правила может быть в прошлом: создаются только ещё не начавшиеся занятия. Предпросмотр явно показывает нулевой результат, если начало за горизонтом или период закончился.

Версия фиксирует IANA-зону филиала (Europe/Minsk по умолчанию); занятия сохраняют timezone, starts_on и абсолютные starts_at/ends_at. Изменение зоны филиала не переинтерпретирует историю и старое правило: новую зону получает следующая версия правила. Длительность — прошедшие минуты, может пересекать полночь. Несуществующее или неоднозначное локальное время при смене DST отвергается вместо тихого сдвига.

Генератор в том же Go-процессе запускается при старте и каждый час, с отменой при SIGTERM и ограничением прохода 45 секунд; после сбоя пробует в следующий час. Он продлевает weekly/day_parity на будущие даты текущего и следующего **локального** месяца, date_list — на весь конечный список. Восстановление не создаёт прошедшие занятия задним числом.

Общий PostgreSQL advisory transaction lock 155007 сериализует создание/предпросмотр/смену правил и генерацию, включая случайный запуск нескольких процессов. Partial UNIQUE(group_id,starts_at) WHERE superseded_at IS NULL не допускает одинаковые живые слоты, в том числе отменённые. Генератор никогда не обновляет существующее занятие. Если позднее разовое занятие заняло слот за прежним горизонтом, сохраняет его, продлевает остальные даты и возвращает конфликт в журнал сервера; администрация исправляет правило. Архив club/group или отзыв/disable тренера прекращают продление, сохраняя историю и уже созданные занятия.

## Датированное изменение и предпросмотр

Изменять можно последнюю версию серии, с будущей/сегодняшней датой строго позже её from и внутри прежнего периода. Группа серии неизменна; для другой группы создаётся другое правило. Смена режима/тренера/времени/конца создаёт новую строку с прежним series_id; старая получает until=дата изменения и увеличенную version. DB-trigger запрещает переписывать содержание/ключи версии и перекрытие интервалов серии.

Предпросмотр возвращает все новые даты, затрагиваемые будущие ordinary planned и сохраняемые исключения/журналы. Подтверждение повторяет расчёт внутри транзакции; SHA-256 токен привязан к нормализованному вводу, старой версии, новым датам и состояниям/версиям затронутых занятий. Изменение между просмотром и сохранением требует нового просмотра (409), а не скрытого применения другого результата. Токен не заменяет авторизацию.

Только будущие `planned`, без ручного override и roster_frozen_at, получают superseded_at и увеличенную version. Записи/ID остаются в истории; рабочие списки исключают их. Новые планы создаются отдельно. Past/open/closed/cancelled/manual/frozen не меняются; отмены/замены/журналы и уже начавшиеся planned старых версий резервируют свою локальную дату серии даже при смене времени. Дата отмены не становится плановой при повторной генерации. Audit изменения старой версии, замещения планов и создания новой версии атомарен с операцией. При отказе аудита всё откатывается.

## API и права

`B=/api/clubs/{clubID}/schedule`.

| Запрос | Контракт |
| --- | --- |
| GET B | Все версии owner/admin своего филиала; trainer — только правила с собственным trainer_id |
| POST B/preview | Input без previewToken → Preview {token,timezone,dates,affected,preserved}; не пишет данные |
| POST B | Тот же Input + previewToken → 201 Rule, либо Session для once |
| POST B/{ruleID}/preview | Input с version старой записи, from=дата применения → Preview |
| PUT B/{ruleID} | То же + previewToken → 201 новая Rule |
| GET B/sessions?from=…&until=… | Session[] за `[from,until)`, максимум 366 дней, без superseded; trainer — только свой фактический trainer_id |

Input: groupId,trainerId,mode,startsTime,durationMinutes,from,until,version; ровно поля режима: weekdays, dayParity (`even/odd`) или selectedDates. Сервер отвергает неизвестные поля/комбинации, пустые/повторные даты и недопустимые периоды. Чужие/несуществующие/неверные ID одинаково 404, 400 invalid_input, 409 session_duplicate/version_conflict/preview_changed/club_archived/group_archived, безопасный 503 not_ready. Ответы no-store; Origin/CSRF обязательны для POST/PUT, включая предпросмотр.

Каждый endpoint auth.Require/RequireClub. Запись и предпросмотр повторно проверяют actor/live session/administrator под `auth.LockClubAdministrator`; затем общий schedule lock → **clubs.RequireActive → groups.ReadGroup(active=true) → auth.RequireTrainer** в той же транзакции. Генератор использует те же lifecycle/назначение guards. Право trainer в филиале не выдаёт ему всё расписание: чтения дополнительно ограничены назначенными rule/session IDs. Полная работа тренера с журналом появится в V1-09.

Аудит содержит club scope/actor/ID/серии/версии/даты/время/параметры правила и факт замещения планов. Без ФИО, контактов, логинов, паролей и токенов. UI сохраняет ввод после ошибок, сбрасывает предпросмотр при правке, блокирует двойную отправку; устаревшая форма предлагает явную загрузку версий. Чтения отменяются, запоздалые мутации игнорируются при смене сотрудника/филиала. Доступные имена select связаны через label/htmlFor.

## Следующие задачи

V1-08 реализована: [календарь и команды занятий](sessions-v1.md) используют существующие training_sessions; повторно не создавать таблицу. Все команды блокируют session FOR UPDATE, проверяют version/status/superseded_at и актуальные права, не редактируют retired планы. Хранят override/cancellation в самой записи. При переносе времени сохранять starts_on как дату исходного вхождения серии либо явно пересмотреть механизм резервирования даты; просто пересчитать starts_on означало бы риск повторной генерации исходного вхождения. `schedule_rule_id` остаётся историческим источником.

V1-09 фиксирует снимок/отметки при первом открытии: правила/генератор не пересобирают состав. Уникальные `(id,club_id)` и `(id,club_id,group_id)` sessions подготовлены для FK снимка. Фактический trainer_id и текущая роль проверяются на каждом запросе. superseded_at не является отменой и не создаёт absent/статистику; такие планы исключаются из рабочего календаря/отчёта.
