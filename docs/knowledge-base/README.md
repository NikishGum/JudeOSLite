# База знаний JudeOSLite / PRIDE

Поддерживаемый контекст будущей внутренней CRM. Исследование публичных материалов проведено 11 октября 2026 года; источники и ограничения сохранены вместе с выводами.

## Порядок чтения для агента

1. [Краткая память](memory.md) — требования заказчика, существенные выводы, неизвестные условия и история исследования.
2. [Контекст CRM](crm-context.md) — предметная область, mobile-first/PWA, вопросы оплаты и посещаемости, ещё не согласованные решения.
3. По теме задачи: [клуб](club.md) или [ЕРИП/iPay](ipay.md).
4. Для проверки происхождения и полноты: [реестр источников](site-inventory.md).

Оформление проекта: [DESIGN.md](../../DESIGN.md), [спецификация дизайн-системы](../../design-system/README.md). Правила работы с репозиторием: [AGENTS.md](../../AGENTS.md).

## Как пользоваться и обновлять

- Требования заказчика, факты публикаций, предложения агента и неизвестные условия имеют разный статус. Не превращать предположение в утверждённое правило.
- Сведения сайта — срез на дату проверки. Тарифы, расписание, состав групп, назначения тренеров и протокол iPay перепроверять перед использованием.
- При новом подтверждённом решении обновлять тематический документ и краткую память, указывая источник, дату и статус. Устаревшее отмечать или заменять, сохраняя существенную причину изменения.
- Не добавлять секреты, доступы, персональные реестры участников, raw-транскрипты и большие логи. Достаточно краткого вывода и ссылки на источник.
- Если доступен qdrant-memory, использовать его по правилам заказчика; эта версия базы в Git остаётся доступной без MCP и служит источником документированного контекста.

На этапе исследования заказчик поручил только собрать контекст, без реализации. Эта запись фиксирует границы выполненного этапа; начинать разработку следует по отдельному поручению пользователя.
