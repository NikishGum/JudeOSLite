## Автоматическая регрессия

Из корня с Docker/Compose, Node 24.19, Python Playwright 1.62:

```sh
cd frontend
npm ci
npm run build
cd ..
docker build -f deploy/Dockerfile -t judeoslite:ci .
python3 -m pip install playwright==1.62.0
python3 -m playwright install --with-deps chromium webkit
python3 frontend/e2e/pwa_v1.py
PWA_BROWSER=webkit python3 frontend/e2e/pwa_v1.py
```

В managed cloud читать skill окружения; Docker build получает CA через
`--secret id=proxy_ca,src="$CODEX_PROXY_CERT"`. `CHROMIUM_PATH` позволяет выбрать
установленный Chromium. Два движка запускаются последовательно: используется
loopback :18081. Скрипт создаёт и в finally удаляет только уникальные pwa161-*
network/app/db; PostgreSQL 18.6 browser161, синтетический owner и пароль.
Рабочие VPS/БД не используются. CI исполняет обе регрессии после production build.

В WebKit сетевые отказы внедряются в отдельный trainer-context с
`service_workers=block`: Playwright routing не перехватывает запросы страницы,
контролируемой worker. Owner/admin проверяют настоящий worker/cache/update.
Задержка обработки ответа для late report/update guard использует временную
обёртку fetch **в тесте**: сервер действительно выполняет запрос, SQL подтверждает
запись, клиент получает ответ после явного освобождения. Production-код не меняется.
Offline reload в Chromium проверяется через browser offline; WebKit проверяет
публичную оболочку при настоящей остановке disposable app с последующим restart
и readiness. Его `set_offline` для navigation завершается внутренней ошибкой до
worker fallback, поэтому этот сигнал не используется как доказательство работы
Safari. Offline mark в отдельном trainer-context проверяется обоими движками.

Путь UI → Go HTTP API → PostgreSQL → UI:

- Owner готовит филиал/администратора; admin через UI создаёт группу, тренера,
  пять участников с одинаковым семейным телефоном и начальным составом.
- Admin через формы создаёт weekly (один выбранный день), odd day_parity,
  date_list (две даты) и once (без rule). Python независимо перечисляет даты;
  предпросмотр и реальные API-сеансы совпадают. Double submit даёт один POST.
- Исторический сеанс на сегодня создаётся в **disposable SQL fixture**, чтобы
  journal flow не зависел от времени запуска CI. Четыре UI-расписания создают
  настоящие будущие сеансы; этот исторический сеанс не выдаётся за созданный UI.
  Двенадцать cancelled SQL fixtures создают длинный список занятий: на 320×480
  после выбора журнал/подтверждение видны без ручной прокрутки, фокус на заголовке.
  До подтверждения серверный статус planned и записей нет. Проверяются ссылки
  «Участники»/«Расписание» и их цели ≥44 px; отменённые fixtures не входят в 40% ledger.
- Trainer открывает снимок пяти карточек: A present, B unknown, C illness,
  D excused; E становится close_default/unknown. Проверены причины, отмена
  панели/Escape/focus cycle, двойной тап, задержка, явный offline, отказ до commit,
  потеря ответа после commit и identical retry без второго audit, reload открытого
  журнала с продолжением с E. Closed — без кнопок записи.
- Admin исправляет C на present с причиной. Owner видит 1 closed, 2 present,
  3 absent, 40%; причины unknown=2, illness=0, excused=1.
- Отмена настоящего open сеанса сохраняет пять unmarked без defaults, запрещает
  запись. Live отзыв trainer-роли блокирует сохранение и очищает снимок.
- 320/390/1280 px, короткая панель 320×480, цели ≥44 px, отсутствие overflow/JS
  errors. Manifest/icons, Chromium installability, static-only Cache Storage,
  offline публичная оболочка/отсутствие API fallback, смена сотрудника/две вкладки,
  expiry/pagehide/pageshow, две реальные сборки/waiting/save guard/другая вкладка.

Скрипт печатает JSON с настоящим engine/version, counts/report и
physicalInstallation=NOT TESTED. Снимки `/tmp/pwa161-{engine}-{screen}-{width}.png`
содержат только disposable synthetic данные. [Контракт PWA](pwa-v1.md).

### Локальные дефекты и исправления

На исходном 88edc2e Node24.19/frontend и arm64 production Docker прошли;
неизменённый E2E **FAIL** на bundled Chromium151.0.7922.34, Chrome154.0.8037.98,
Edge155.0.4283.45 (D1) и Mac Playwright WebKit26.5 (D2, затем D3 в диагностике).
Диагностические копии с обходами не считаются PASS исходной регрессии.

- **D1:** cache_check требовал один кеш до активации waiting B. Два versioned
  static-only кеша в этот момент корректны. Регрессия теперь удерживает A
  дополнительной вкладкой, проверяет точные кеши A/B до explicit update,
  затем controller activation/reload и единственный B. Проверки приватности
  сохраняются для обоих кешей.
- **D2:** native appearance в Mac WebKit давал select 24 px. Select использует
  appearance:none и стрелку в CSS с цветом PRIDE; настоящий HTML select,
  подписи и нативный выбор опций сохраняются, применяется цель ≥44 px.
- **D3:** нативный Tab от средней кнопки мог уходить на BODY. ActionSheet
  явно переводит фокус при каждом Tab/Shift+Tab, включая heading/wrap/disabled;
  Escape и возврат фокуса сохранены. E2E проверяет каждую кнопку в обоих направлениях.

Исправления прошли Cloud/Linux регрессию/CI и повтор исходных Mac тестов
без диагностических обходов. Select/date/contact, panel Tab/Shift+Tab/Escape
на Mac и native select/panel/relaunch iPhone повторены на f532e6b; результаты ниже.
