# Расписание и страница тренировки — постановка #216

20.10.2026 · [issue #216](https://github.com/NikishGum/JudeOSLite/issues/216).
Источник требований: прямой запрос заказчика и четыре скриншота его онлайн-школы
(desktop/mobile расписание и desktop/mobile lesson). Исследование ниже проверено
по публичной официальной документации; закрытые кабинеты сервисов не тестировались.
Постановка сохранена как источник требований. Реализация #216 и её проверки описаны
в [протоколе](sessions-weekly-validation.md); исторические указания «не реализовывать»
ниже относятся к исходному исследованию, не к последующему поручению реализации.

## Подтверждено заказчиком

- Пересмотреть раздел «Занятия» и страницу конкретной тренировки для тренера,
  администратора и владельца.
- На компьютере ориентироваться на неделю с колонками дней и занятиями внутри.
  На телефоне использовать читаемое
  вертикальное представление, как на приложенном мобильном расписании.
- Навигация назад/вперёд по неделям, «Сегодня», понятные даты, время и длительность.
- У каждой тренировки есть отдельная страница и постоянный адрес; из расписания
  можно перейти к конкретному занятию и его участникам.
- Уточнение в этом же чате: **в расписании не показывать спортсменов**, включая
  превью имён и «Ещё N». Нажатия на имя в расписании тоже нет. Состав доступен
  на странице тренировки. В карточке администратору/владельцу виден тренер;
  в тренерском представлении собственное имя тренера не дублируется.
- Исследовать аналоги, предложить варианты и изменить #216. Реализация приложения
  этим поручением не начинается; задача остаётся Todo, без исполнителя.

Новое поручение заменяет прежнее решение #216 о «Повестке дня» по умолчанию
и запрет недельных колонок. Старый HTML варианта А остаётся историческим
референсом, а не обязательной композицией. Сохраняются предыдущие требования
к последовательной отметке, правам, существующим операциям и настоящим API.

## Варианты композиции

| Вариант | Сильная сторона | Ограничение | Рекомендация |
| --- | --- | --- | --- |
| Недельные колонки с карточками по времени | Максимально близко к скриншоту; неделя видна целиком, компактные сведения о тренировках | Совпадение времени в разных днях не выровнено по вертикали | Основной вид desktop; состав только на странице тренировки |
| Почасовая недельная сетка | Видны свободные интервалы и параллельные занятия | Длинный день даёт много пустого пространства, короткие события тесны для сведений | Альтернатива для будущего планирования; сейчас не реализовывать |
| Повестка: вертикальные дни и занятия | Удобна для телефона и плотной ежедневной работы | Слабее сравнение всей недели на широком экране | Мобильное представление той же недели; отдельный режим «День» сохранить |

Предлагаемое сочетание: **недельные колонки на широком экране → вертикальные
блоки дней на узком → одна страница тренировки**. Не нужны три новые реализации
календаря или переключатель демонстрационных концепций.

## Уточнения заказчика после исследования

Ответы на оба вопроса получены 20.10.2026: имена спортсменов и переходы по ним
из расписания исключены. Превью нескольких случайных имён не помогает обзору
групповой тренировки. Первоначальная рекомендация «3–5 имён и Ещё N» отменена.
В расписании нужны базовые сведения о занятии и ролевое отображение тренера.
Полный состав, поиск и посещаемость находятся на странице тренировки.

## Расписание

Режим Operate, существующая идентичность PRIDE: Rubik, красный акцент, белые
панели, актуальные DESIGN.md и design-system/README.md. Скриншоты онлайн-школы
задают структуру и переходы; её цвета, IND, предметы и элементы браузера
не становятся данными/оформлением клуба.

- Неделя по умолчанию: понедельник–воскресенье вокруг выбранной даты, как
  в существующем контракте PRIDE. В URL сохранённый выбор имеет приоритет.
  Назад/вперёд сдвигают неделю на семь дней, «Сегодня» возвращает текущую неделю
  и выделяет текущий день в timezone филиала. Выбор даты открывает её неделю.
  В шапке один комплект навигации и видимый диапазон дат, в том числе на стыке
  месяца/года; существующий дополнительный режим «День» листает дни.
- На широком экране семь колонок, в каждой дата/день недели/число занятий,
  ниже карточки по возрастанию фактического времени. Пустой день виден явно.
  Это колонки списков, а не таблица с общей почасовой осью: высота карточки
  определяется содержимым. Совпадающие по времени занятия не перекрываются.
- Если ширины для семи читаемых колонок недостаточно, переходить к вертикальным
  дням; границу проверить на реальном layout с Sidebar. На телефоне все дни
  выбранной недели идут вертикально, можно перейти к сегодняшнему блоку.
  Горизонтальной прокрутки страницы и сжатых семи колонок нет.
- Карточка: начало–конец и длительность, название группы, дата в заголовке дня,
  текстовый статус. Администратор/владелец видит фактического тренера;
  тренер в своём тренерском контексте — без повторения собственного имени.
  Для многоролевого сотрудника использовать текущий разрешённый контекст:
  административный обзор показывает тренеров, вход в свои занятия — не дублирует.
  Новый переключатель ролей ради карточек не вводить. Состава, превью имён,
  «Ещё N» и сводки посещаемости в карточке нет — они на странице тренировки.
  Разовое/перенос/замена
  показаны только при подтверждённых данных; причина отмены доступна явно.
  Не выводить возраст и тренера из свободного названия группы.
- Одна заметная ссылка времени/названия открывает тренировку. Меню имеет
  собственную доступную цель; не вкладывать ссылки/кнопки друг в друга.
  На телефоне переход тоже явный; только hover не используется.
- Фильтры группы, фактического тренера и статуса применяются немедленно;
  сброс понятен. Карточки, счётчики дней и итог недели отражают один набор
  и одинаковые фильтры. Тренеру не предлагать недоступные группы/чужие занятия.
- «Сейчас» вычислять по startsAt ≤ now < endsAt для неотменённого,
  незавершённого занятия, независимо от того, открыт ли журнал. Статус журнала
  показывать отдельно: прошедший open не означает «идёт сейчас».
- В недельном обзоре завершённые и отменённые не исчезают автоматически;
  отменённые имеют текстовый статус. В режиме дня можно приоритизировать
  текущие/предстоящие, сохранив явный доступ к завершённым и незакрытым журналам.
- Сохранить «Период» до 366 дней включительно, четыре режима расписания,
  предпросмотр/версии/историю правил, разовое занятие, перенос, замену и отмену.
  Редкие команды доступны в меню, редактирование имеет прежние guards.

## Страница конкретной тренировки

Термин для английских идентификаторов — **training session**, коротко `session`.
Сущность `training_sessions` и UUID уже существуют. `workout` чаще обозначает
набор упражнений; новую параллельную сущность ради названия вводить не нужно.

Предлагаемый канонический frontend-маршрут:
`/clubs/:clubId/sessions/:sessionId`. Это адрес страницы, а не новый механизм
посещаемости. Он должен работать по прямой ссылке, после входа и при reload,
в том числе без предварительной загрузки календаря/параметров диапазона.
Старый `/clubs/:clubId/sessions?session=…` и параметр `journal` сохранить
совместимыми и нормализовать в ту же страницу без отдельного UI.

Ссылка «К расписанию» восстанавливает период, вид, группу, фильтры и положение
просмотра, если они были переданы/сохранены. При прямом входе без контекста
возврат ведёт в неделю фактической даты тренировки. В URL — только разрешённые
ID и параметры календаря, без имён, контактов, отметок и свободных return URL.
Неизвестный/недоступный ID не заменять первой доступной тренировкой.

В шапке — группа, полная дата, начало–конец, длительность, фактический тренер
(обязательно для admin/owner, без лишнего повторения в своих тренерских занятиях),
филиал и timezone, текстовый статус, происхождение/перенос/отмена. Если занятие
переходит полночь, видна дата окончания. Действия соответствуют роли и состоянию.
Ниже — полный состав с поиском по имени для длинных списков и рабочая область
журнала. На desktop они расположены рядом; на телефоне — в одной колонке,
основное действие доступно без длинной прокрутки состава. Не копировать большой
пустой правый блок урока онлайн-школы. Рекомендуемые подписи CTA:
«Открыть журнал» с существующим подтверждением для planned, «Продолжить отметку»
для open, «Посмотреть журнал» для чтения. До разрешённого дня открытия planned
показывает состав для чтения и понятное ограничение, не активное действие записи.

## Состав страницы до и после открытия — обязательный контракт

Текущий календарный `Session` не содержит имён/размера состава или сводки
посещаемости. Planned-журнал читает только уже зафиксированные attendance_records;
его пустой массив нельзя считать отсутствием спортсменов в группе.

- **До фиксации:** показывать «Предварительный состав на [дату]», рассчитанный
  по существующим датированным group_memberships на фактическую локальную дату
  занятия. Переводы учитываются по тем же интервалам, что при открытии журнала.
  Это прогноз состава, не запись участия, бронирование или факт присутствия.
- **После фиксации:** показывать только snapshot attendance_records, включая
  замороженный пустой состав и сохранённые записи cancelled. Текущий состав
  группы не заменяет исторический снимок. Имена/признак архива — как в текущем
  контракте журнала; контракты персональных данных не расширяются.
- При cancelled без снимка прямо обозначить предварительный источник,
  не создавать несуществовавшую историю посещения. Неизвестное/ошибку не
  подменять нулём. До снимка показывать «Журнал ещё не открыт», а не «0 посещений».
- Состав и сводку получать только для выбранной тренировки. Календарю они
  не нужны: не добавлять превью/подсчёты спортсменов в календарный API ради
  отменённой идеи. Не GET журнала/группы на каждую карточку или день;
  неделя/период используют календарный набор без N+1.
- Чтение календаря, страницы и предварительного состава не открывает журнал,
  не создаёт attendance_records/roster_frozen_at и не меняет версии журнала.
  После явного открытия UI перечитывает фактический снимок; он может отличаться
  от ранее показанного предварительного состава при конкурентном переводе.
- Сервер проверяет разрешённый филиал, live роли и actual trainer для каждого
  чтения. Для тренера достаточно разрешённых имён и membership ID; не выдавать
  чужие занятия, контакты, дату рождения или административные причины коррекции.

Добавить минимально недостающее чтение предварительного состава выбранной
тренировки в рамках #216. Точную форму JSON
исполнитель фиксирует после аудита текущего main; новые write endpoints журнала,
дублирование снимка, хранилища и миграции без необходимости не допускаются.

## Роли и сохранение отметки

| Роль | Обзор и страница | Действия |
| --- | --- | --- |
| Тренер | Только фактически назначенные ему тренировки в разрешённом контексте | Текущий последовательный журнал; closed/cancelled для чтения |
| Администратор | Занятия назначенного филиала | Существующие календарные операции; коррекция одной closed-отметки с причиной/историей |
| Владелец | Разрешённые филиалы через существующий выбор контекста | Те же управленческие действия; новый межфилиальный календарь не требуется |

Многоролевой сотрудник отмечает только при живой trainer-роли и фактическом
назначении. Admin/owner сами по себе не получают trainer-write.
Переиспользовать SessionDetail, SessionJournal, AttendanceCards, AdminJournal.
Сохранить порядок вызова, «Присутствует»/«Отсутствует», три причины,
предыдущего участника, сводку и завершение. Переход к следующему — после успеха
сервера; ошибка сохраняет текущую карточку/ввод, двойной submit запрещён,
409 требует актуализации. При закрытии неизменённые правила absent/unknown,
атомарность, идемпотентность, история, причины коррекции и no-store сохраняются.
Новый обзор состава не добавляет вторые формы отметки, массовую отметку,
свайпы или офлайн-очередь.

## Адресная приёмка реализации

- Desktop и mobile: недельная навигация, границы месяца/года, «Сегодня» в зоне
  филиала, все/пустые дни, переключение в день/период, фильтры и их счётчики.
- Карточка → тренировка → возврат; отсутствие превью спортсменов в расписании,
  ролевое отображение тренера; прямой URL, reload/back/forward,
  старые ссылки из групп, главной, уведомлений и журналов, смена филиала.
- Planned с составом/без состава, конкурентный перевод до open, frozen пустой,

## Контракт реализации #216 · 20.10.2026

Канонический маршрут `/clubs/:clubId/sessions/:sessionId` использует прежние
GET журнала тренера/администратора. Старые query-ссылки нормализуются на ту же
страницу. Общий `sessionHref` обновляет ссылки главной и отчётов; в списках
журналов есть ссылка «Страница тренировки». Поля календаря в URL: `group`,
`from`, `through`, `view`, `trainer`, `status`, `scroll`, `journal`; произвольный
return URL и персональные данные не принимаются. Без контекста возврат ведёт
в неделю фактической даты тренировки. Смена филиала сбрасывает старый контекст.

Ответы существующих журналов `{session, records}` дополнены полем `roster`:

```json
{
  "source": "preliminary",
  "date": "2026-10-20",
  "members": [{"membershipId": "UUID", "fullName": "Имя", "archived": false}],
  "summary": null
}
```

После freeze `source="snapshot"`, members происходят из тех же records,
а summary содержит целые `present`, `absent`, `unmarked`. Пустой snapshot
возвращает пустой members и нулевые счётчики; до freeze summary всегда null.
Это добавочное чтение, records и все команды open/mark/close/correct совместимы.
Для preliminary используется фактическая сохранённая локальная дата занятия
и интервалы `valid_from <= date < valid_until`, включая отсутствие верхней
границы. Архив карточки показывается тем же признаком, что в журнале. Cancelled
без freeze остаётся preliminary с явным объяснением, что это не история посещения.

Поле Session `previousTrainerName: string | null` происходит из последнего
подтверждённого `replace-trainer` audit event для фактического trainer ID;
manualOverride не используется как признак замены. Календарь читает всё одним
SQL-набором с индексированным подзапросом к истории; составы/сводки не добавлены
в календарный ответ. Тренер получает прежний безопасный контракт имён/ID,
без контактов/даты рождения/объяснений коррекции. Все новые данные читаются
внутри существующих live-проверок прав, блокировок и no-store.

Композиция расширяет текущую дизайн-систему: 7 колонок при ширине содержимого
не менее 980px, вертикальные дни ниже этого порога, включая Sidebar. Рабочая
область страницы предшествует длинному составу на телефоне. До открытия
нет фиктивных «0 посещений»; «Сейчас» зависит от реального интервала, не от open.
Миграций, новых write endpoints, второго снимка/алгоритма отметки нет.
