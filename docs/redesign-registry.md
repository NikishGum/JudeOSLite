# RD-02: реестр, состав и управление

Реализация #184, 14.10.2026. Визуальный мир — выбранная [Working Panel](../design-system/prototypes/dashboard/DESIGN.md), [preview](../design-system/prototypes/dashboard/preview.html) и [PRIDE](../DESIGN.md); общие ресурсы и исходные токены не изменены.

## Предметные экраны

Участники, группы и тренеры всегда относятся к конкретному доступному филиалу. Его имя есть в заголовке и редакторе. «Вся сеть» предлагает выбор филиала; только управление владельца филиалами/администраторами является сетевым. Trainer-only не получает реестр, контакты или управление сотрудниками; собственные занятия остаются из разрешённого trainer API. Ролевые главные и «Мои группы» RD-05 здесь не реализуются из общего реестра.

Списки — выровненные строки на ПК, последовательные карточки на телефоне без горизонтального скролла. Статусы написаны текстом. Карточка участника, состав на дату и история интервалов читаются в основной области. Их рамки не вложены друг в друга. Редакторы участников/групп/тренеров/филиалов/назначений используют native Dialog RD-01: справа на ПК, снизу на телефоне, прокрутка панели/safe-area, фокус/Tab/Shift+Tab/Escape/возврат.

Форма участника сохраняет полные ФИО/дату рождения, вступление, вид/значение локального контакта, контактное лицо и атомарную начальную группу с датой. Совпадающие ФИО и семейные контакты не объединяются. `canEditIdentity` определяется сервером: администратор может править локальную идентичность; общую для нескольких филиалов — только владелец. Контакт остаётся локальным. Архив/возврат и version/participantVersion сохранены.

Группы сохраняют создание, название, архив, состав на дату, поиск участника, включение/исключение/перевод и историю. Начало интервала включено, конец исключён; прежние снимки занятий не меняются. Архив явно объясняет запрет новых включений и сохранение истории. Сотрудники сохраняют создание, аккаунт/пароль/отключение, отзыв/добавление trainer-назначения и несколько admin/trainer-назначений. Пароли очищаются после отправки, в URL/storage/history их нет. Архив филиала объясняет запрет будущих операций и сохранение уже существующих занятий.

## Навигационный контракт для RD-03/RD-05

- `/clubs/:clubId/participants?detail=:membershipId` остаётся контрактом RD-01.
- `/clubs/:clubId/groups?detail=:groupId` открывает настоящий состав с GET разрешённого group roster. Reload/back/forward восстанавливают выбранный ID; дата чтения начинается с текущей локальной даты филиала. «Закрыть состав» убирает detail. Чужой ID получает серверную ошибку, а не фиктивное содержимое.
- «К занятиям группы» ведёт в `/clubs/:clubId/sessions?group=:groupId`. `readRoute`/`routePath` переносят UUID в поле `Route.group`. **Применение и отображение фильтра календарём — RD-03**; RD-02 проверяет транспорт ID и не реализует занятие заново. Фильтр не даёт прав, одинаковые имена не подменяют ID.
- Смена раздела/филиала очищает detail/group. History содержит только URL и prideIndex. Для RD-05 доступны existing participant detail и group detail/navigation adapters; новые счётчики/дашборды не добавлены.

## Сохранение и контекст

Серверные права, API и CSRF не изменены. App использует прежний ключ всех назначений/user/owner/club/timezone: смена scope размонтирует предметную область, отменяет GET и удаляет прежнюю карточку/черновик. Lifecycle/pagehide/pageshow/BFCache cleanup, PWA и API generation остаются RD-01. Pending POST/PUT не отменяется переходом.

Редактор держит фокус, фон native dialog inert. «Отмена» явно отбрасывает форму без записи. Закрытие панели/Escape проходит existing draft guard; отмена подтверждения возвращает форму и фокус. Во время save закрытие запрещено, глобальная навигация/PWA update ждут ответа. Ошибка/конфликт находятся в панели, правки не перезаписываются. Явное перечитывание предупреждает о сбросе. Save/архив обновляют предметный список/карточку; изменение интервала — историю и видимый состав. Поиск не перечитывает справочник групп, roster не перезагружает весь реестр. Сбой загрузки групп внутри формы имеет свою кнопку повторения.
