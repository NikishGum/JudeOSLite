# Промпт нового агента-исполнителя

Для порученного этапа RD использовать [план редизайна](development-plan-redesign.md), [реестр RD](github-issues-redesign.json) и название `RD-xx · #номер — результат`. Та же очередь `python3 scripts/claim_issue.py НОМЕР` проверяет оба реестра и межэтапные зависимости. V1-номера ниже относятся к завершённому предыдущему этапу. Стартовый промпт RD-01: [redesign-first-agent-prompt.md](redesign-first-agent-prompt.md).

Это инструкция для задачи, которую пользователь поручил в отдельном чате. Ручное назначение не требуется: агент выполняет его через общую очередь GitHub. Полный реестр — docs/github-issues-v1.md. Не использовать удалённый #1 или старый DEC-01.

Первым действием переименуй свой чат через доступный инструмент `set_thread_title` в точное название из стартового промпта. Если названия нет, составь «V1-xx · #номер — краткий результат» по выбранному issue. При отсутствии инструмента сообщи об этом; не утверждай, что переименование выполнено.

Прочитай AGENTS.md, docs/knowledge-base/README.md и memory.md, docs/collaboration.md, architecture-v1.md, development-plan-v1.md и полное выбранное issue.

Реализуй только порученную задачу. Получи свой GitHub-аккаунт через `gh api user --jq .login`. Проверь live issue и зависимости; назначенное другому человеку или другому чату issue не бери. Даже совпадение исполнителя с твоим аккаунтом не разрешает второму чату начать ту же работу. Не меняй чужого владельца; продолжение/передача ранее начатой работы — только по явному поручению и после проверки отсутствия параллельной работы.

Для свободной готовой задачи выполни из актуального main `python3 scripts/claim_issue.py НОМЕР`. Дождись результата своего workflow: acquired=true, один исполнитель — аккаунт отправителя, метка In progress. Только после подтверждения начинай код. Не назначай напрямую через gh issue edit/PATCH: общая очередь исключает гонку двух агентов. Отказ/отмена/ошибка/таймаут не дают права работать; при неизвестном результате проверь run URL/request ID перед повтором. Сохрани успешный run URL в контексте этого чата для возобновления работы.

Проверь все прямые зависимости: закрыты, результат уже в main и проверки пройдены. Для V1-01 зависимостей нет. Используй отдельную ветвь codex/v1-01-foundation (или по выбранному ID); при параллельной работе изолированный рабочий каталог. Не захватывай чужие незавершённые изменения. Согласуй правку общих файлов/миграций до начала.

Сделай весь состав выбранной задачи, включая миграции, API/UI там, где они предусмотрены, проверки и документацию. Не переименовывай/сокращай критерии по своему усмотрению. Приоритет — работающая простая версия: Go net/http + SQL/pgx, React/TypeScript, PostgreSQL, Compose; библиотеки/версии сверить по официальным источникам. Не создавать будущие финансы, iPay, медицинские сущности, Excel, микросервисы или универсальную платформу.

После проверок создай коммит, отправь в репозиторий без force push и проверь отправку. Доставь результат в main в пределах поручения и правил репозитория; PR/ревью коллеги необязательны. Issue закрывается после фактической готовности в main; автоматическая метка Done следует за закрытием. Не объявляй развёртывание, реальные устройства или приёмку выполненными без проверки.

Один issue — один чат; пользователь создаёт следующий чат сам. Существенные решения и ограничения сохраняй в тематических документах и docs/knowledge-base/memory.md, чтобы следующему чату не требовалось читать всю переписку.

В отчёте: что работает, что проверено, коммит/PR, существенные ограничения. Затем предложи следующую доступную задачу по актуальным зависимостям и live статусам: ID/ссылка, почему она следующая, готовность зависимостей и один копируемый промпт, который сам задаёт название и назначение. Если всё заблокировано, укажи блокер. Не резервируй следующую задачу из заканчиваемого чата — её занимает агент нового чата после поручения пользователя.

Шаблон промпта (подставить реальные название, ID, номер и URL):

```text
Переименуй этот чат через set_thread_title в «V1-xx · #номер — краткий результат».
Работаем над JudeOSLite, задача V1-xx: URL_ISSUE.
Прочитай актуальные AGENTS.md, docs/knowledge-base/memory.md,
docs/collaboration.md, docs/task-agent-prompt.md и полное live issue.
Проверь зависимости в main и отсутствие исполнителя/другого работающего чата.
Автоматически займи задачу через python3 scripts/claim_issue.py НОМЕР;
дождись acquired=true, назначения моего подключённого GitHub-аккаунта и In progress.
При отказе или неизвестном результате не начинай код и не обходи очередь.
Выполни задачу целиком, проверки, коммит/push и завершение по правилам проекта.
В конце предложи следующую доступную задачу и готовый промпт для нового чата.
```
