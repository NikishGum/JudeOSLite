# Реалистичные демо-данные Беларуси

По поручению заказчика19.10.2026, [RD-13 / #210](https://github.com/NikishGum/JudeOSLite/issues/210).
`seed-demo` добавляет связанную вымышленную сеть в настоящие таблицы CRM. Данные
доступны через обычные экраны/API, с действующими правами сотрудников и родителей.
Загрузка выполняется отдельной административной командой; запуск сервера её не вызывает.

## Состав

| Сущность | В одном филиале | Всего |
| --- | ---: | ---: |
| Филиалы | — | 3: Минск · Уручье, Брест · Восток, Гродно · Девятовка |
| Тренеры | 5 | 15 |
| Администраторы | 2 | 6 |
| Группы, по две на тренера | 10 | 30 |
| Дети, по20 в группе | 200 | 600 |
| Семьи | 150 | 450 |
| Родительские аккаунты, по два на семью | 300 | 900 |
| Тарифы | 3 | 9 |
| Счета / абонементы | 600 / 600 | 1800 / 1800 |
| Учебные PDF-документы четырёх категорий | 160 | 480 |

Дополнительно создаётся один владелец. У детей нет отдельного входа: существующая
модель даёт доступ родителям через семейную связь. Из450 семей150 имеют двоих
детей,300 — одного. Имена/отчества и склонения фамилий согласованы; отчество
ребёнка соответствует имени отца. Контакты семьи продублированы в карточках детей.
Адреса залов иллюстративные, не утверждение о реальных филиалах PRIDE.
Телефоны синтетические вида `+375 29 000 00 00`, email на `example.com`;
не звонить и не использовать их для рассылок.

Дата по умолчанию — день запуска в `Europe/Minsk`. Диапазон занятий — от даты
минус42 дня включительно до даты плюс28 дней исключительно. Для даты19.10.2026
это07.09–15.11:915 занятий,543 закрытых. Есть недельное расписание, чётные даты,
список дат и разовые воскресные занятия. В каждом филиале есть отменённые занятия,
будущая замена тренера, один незавершённый прошлый журнал и один частично
заполненный журнал на выбранный день. Каждый закрытый журнал содержит20 отметок:
16 присутствий и4 пропуска; встречаются все три причины пропуска.

Тарифы —80/110/140 BYN за8/12/16 посещений на28 дней. У каждого ребёнка три
непересекающихся периода абонемента: прошлый, текущий и будущий. Есть paid/pending/void,
аннулированные абонементы и четыре ручных метода оплаты. Использованные посещения
считает существующий backend по закрытым журналам; seed не записывает фиктивный
остаток. Пометка `erip` означает ручную запись, реального iPay-платежа нет.

Документы используют готовый модуль из main358d03e (#203). У120 детей есть
по четыре учебных PDF: медицинский допуск, договор, согласие и памятка; у остальных
карточек можно проверить пустое состояние. Файлы открываются настоящим PDF-reader,
содержат крупную пометку DEMO и пояснение, что это учебный образец без персональных
или медицинских сведений, подписей и печатей. Для медицинской категории есть
истёкшие, близкие к окончанию и действующие даты. Скачивание идёт через штатную
проверку семейного доступа; публичных файловых ссылок нет.

Уведомления **не загружаются**: backend пока отдельно в #204. Внешние сообщения
не отправляются. В системе нет дополнительных видов сотрудников помимо владельца,
администратора, тренера и родителя.

## Docker Compose из checkout

Сначала собрать/запустить приложение по README. Для отдельного демо-стенда можно
использовать отдельное имя Compose-проекта (`-p pride-demo`) и свободный APP_PORT,
получив собственный volume. Следующие команды используют обычный проект README.

Предпросмотр без подключения к БД и без записи:

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml exec app \
  /app/seed-demo --date 2026-10-19
```

Загрузка (можно опустить `--date`, чтобы использовать сегодняшний день):

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml exec app \
  /app/seed-demo --apply --date 2026-10-19
```

Команда дважды запросит пароль скрытым вводом (12–128 байт). Он применяется ко всем
**новым демо-аккаунтам**, в Git/аудит/вывод не попадает. Действующие пароли и аккаунты
сохраняются. На чистой демо-БД отдельный `create-owner` не нужен: владелец уже есть.
Для автоматизированного локального запуска допускается `SEED_DEMO_PASSWORD` через
окружение; аргумента пароля нет. Не вводить настоящий пароль литералом в shell history.

Список всех логинов с ФИО, ролью, филиалом и семьёй (без паролей и доступа к БД):

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml exec -T app \
  /app/seed-demo --list-accounts > demo-accounts.json
```

Войти владельцем: `owner.pavel.rudakov`. Примеры остальных ролей команда выводит
в `exampleAccounts`; полный список — в `demo-accounts.json`. Один выбранный при
загрузке пароль позволяет последовательно проверить все роли. Это демонстрационные
учётные записи; используйте их в своём демо/тестовом окружении.

## Действующий тестовый VPS

После обычного деплоя образа с `/app/seed-demo` владелец сервера может выполнить
в root-терминале следующую команду. Имя контейнера соответствует текущему
Compose-проекту `judeos-test`; при изменённом имени его видно в `docker ps`.
Реквизиты БД берутся из уже работающего контейнера, копировать их не требуется.

```sh
docker exec -it judeos-test-app-1 /app/seed-demo --apply
docker exec judeos-test-app-1 /app/seed-demo --list-accounts > demo-accounts.json
```

Если бинарник отсутствует, сначала требуется новый обычный деплой. Выполнение
проверок в Cloud не загружает данные на VPS. Команда добавит три филиала к уже
имеющимся; прежние QA-филиалы и приёмочную историю она не очищает.

## Go без Compose

Нужны Go1.27.2, PostgreSQL18 и переменные подключения, как в README.
Команда миграции выполняется отдельно; seed не меняет схему.

```sh
cd backend
go run ./cmd/migrate
go run ./cmd/seed-demo --date 2026-10-19
go run ./cmd/seed-demo --apply --date 2026-10-19
go run ./cmd/seed-demo --list-accounts > ../demo-accounts.json
```

## Повторный запуск и сохранность

Вся загрузка и её маркер в `audit_events` фиксируются одной транзакцией. При
конфликте логина/ID либо другой ошибке данные этой попытки откатываются полностью.
Существующие филиалы, сотрудники и история не удаляются и не переименовываются.
Два одновременных запуска сериализуются advisory lock.

После успешной загрузки повтор возвращает `alreadyLoaded: true`, исходную дату
и исходные счётчики. Другой `--date` **не сдвигает** историю, другой пароль
**не сбрасывает** вход, ручные изменения карточек сохраняются. Это снимок на дату
первой загрузки. Для свежего независимого набора используйте отдельную демо-БД;
автоматического удаления/очистки существующей сети в команде нет.

Загрузчик выполняет ANALYZE заполненных таблиц, чтобы первые запросы к свежей БД
использовали актуальную статистику планировщика. Бизнес-ограничения и триггеры
работают во время всей загрузки; их отключения нет.

## Проверка

```sh
cd backend
# TEST_DATABASE_URL — только тестовая PostgreSQL с правом CREATE DATABASE.
go test -race ./internal/demodata ./cmd/seed-demo
```

Интеграционный тест создаёт и удаляет только собственную временную БД. Он проверяет
атомарный откат при позднем конфликте, конкурентный повтор, численность/связи,
целостность закрытых журналов, три причины пропуска, BYN, четыре категории PDF,
сроки документов, скачивание byte-for-byte, вход четырёх ролей,
изоляцию филиалов/семей, сверку отчёта с SQL, подтверждение счёта через API и
сохранность ручных изменений при повторе. Без TEST_DATABASE_URL явно SKIP.
