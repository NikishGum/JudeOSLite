# Мобильные карточки посещаемости V1-10

12.10.2026, [#158](https://github.com/NikishGum/JudeOSLite/issues/158). Тренер выбирает своё фактическое занятие и открывает журнал. Используются существующие [API, снимок и права V1-09](attendance-v1.md); backend и миграции этой задачей не меняются.

## Работа тренера

В открытом журнале показывается одна карточка: ФИО, группа, порядковый номер, текущая отметка и признак архива. Короткий стабильный код локальной карточки (последние восемь знаков membershipId) помогает различать одинаковые имена; он не является новым ключом API. Контакты и дата рождения тренеру не выдаются.

Две крупные кнопки «Присутствует» / «Отсутствует», без свайпов. Присутствие сразу отправляет запрос. Отсутствие открывает нижнюю панель «Неизвестна», «Болезнь», «Уважительная»; выбор отправляет запрос. Болезнь — причина отсутствия, медицинские документы не создаются. Видимая отмена и Escape закрывают панель без записи. Пока запрос выполняется, повторные команды и отмена блокируются.

Переход происходит **только после успешного ответа сервера**: следующий неотмеченный участник по порядку, затем оставшиеся в начале списка; когда неотмеченных нет — сводка. Прогресс вычисляется из серверных записей. Через «К сводке и предыдущим отметкам» можно открыть любую запись и исправить её до закрытия. Перезагрузка или повторный вход загружает актуальный журнал и начинает с первого неотмеченного; клиентскую позицию и очередь отметок не храним.

«Завершить журнал» доступно и с неотмеченными, и при пустом составе. Отдельная панель показывает точное число будущих absent/unknown и предупреждение о запрете исправлений тренером после закрытия. «Продолжить отметки» / Escape ничего не закрывает. Сервер выполняет атомарное закрытие V1-09, клиент отображает полученную сводку.

## Ошибки, доступность и состояния

Ошибки связи сохраняют текущую карточку/выбранную причину, не меняют прогресс и не показывают ложного сохранения. Есть явный повтор; после потери ответа запрос мог уже попасть в БД, поэтому повтор использует существующую идемпотентность API. После 409 запись и завершение блокируются до явной загрузки актуального журнала со сбросом ввода. После 401/404 недоступные данные очищаются; 401 также завершает сессию через общий API-клиент. Поздний ответ после смены занятия/филиала/аккаунта игнорируется размонтированным компонентом.

Closed/cancelled показывают только сводку и пояснение; отмена не создаёт автоматические отсутствия. Пустой снимок явно обозначен. Карточки и сводка переносят длинные имена на 320 px. Кнопки причин и основных отметок ≥56 px, остальные ≥44 px. Native modal dialog делает фон недоступным; фокус начинается на заголовке, Tab/Shift+Tab циклически перемещаются внутри панели, Escape отменяет, закрытие возвращает фокус. После перехода к следующей карточке фокус получает её заголовок. Панель прокручивается на коротком экране, учитывает safe area и блокирует прокрутку фоновой страницы. Анимаций нет.

## Воспроизводимая проверка

`python3 frontend/e2e/attendance_v1.py` теперь проверяет совместный пользовательский сценарий V1-09/V1-10. Только disposable loopback `http://127.0.0.1:8080`, соответствующий APP_ORIGIN и AUTH_INSECURE_LOCAL=true; собранная статика. PostgreSQL 18.6: контейнер `attendance158-db` (ATTENDANCE_TEST_DB_CONTAINER допускает только префикс attendance158-), пользователь test, БД browser158. Bootstrap owner / synthetic-browser-password создаётся интерактивной штатной командой; все остальные участники/сотрудники синтетические. Нужны Python Playwright и Chromium; CHROMIUM_PATH по умолчанию /usr/bin/chromium.

Проверки: присутствие и каждая причина; отмена кнопкой/Escape без записи; touch и клавиатура; удержанный ответ и двойное нажатие; потерянный ответ после реального commit, повтор без второго аудита и переход по актуальной сводке после изменения в другом окне; возврат/исправление; reload с серверным состоянием; конкурентная правка/409/явное обновление; подтверждение/отмена/сбой/повтор закрытия с неотмеченными; empty/closed/cancelled; фактическая замена тренера, отзыв роли/сессии, очистка недоступных данных и logout. Сверяются настоящие snapshot/marks/audit/status в БД. 320/390/1280 px и короткий экран 320×480, отсутствие горизонтального overflow/JS errors, размеры кнопок. Снимки `/tmp/attendance158-card-{320,390,1280}.png`, `/tmp/attendance158-sheet-320.png`.

Production TypeScript/Vite и Docker, Go gofmt/vet и полный PostgreSQL `go test -race ./...` проверяются вместе с результатом задачи. Финальные SHA/CI/main — в live issue. Эмуляция Chromium не является проверкой настоящих iPhone/Safari, Android/Chrome или установленной PWA; это остаётся V1-16. Журнал администратора и коррекция closed — V1-11.
