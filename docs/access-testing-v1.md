## Исполняемые сценарии

`backend/tests/integration/access` собирает все предметные HTTP handlers в том же
порядке, что `cmd/server`, и отправляет прямые запросы с настоящими серверными
сессиями/CSRF. Используются PostgreSQL и все текущие миграции. Каждый из восьми
тестов создаёт собственную временную БД `judeos_access_*`, а cleanup удаляет только
её. Все имена, адреса и пароли синтетические.

Два филиала, разные контакты/группы/правила/занятия, открытые и закрытые журналы;
11 профилей доступа: владелец, два локальных администратора, администратор обоих
филиалов, два локальных тренера, тренер обоих филиалов, администратор A/тренер B,
тренер для замены в A, сотрудник без назначений и запрос без входа.

| Область | Владелец | Администратор | Тренер |
| --- | --- | --- | --- |
| Обнаружение филиалов | Сеть | Свои | Свои |
| Филиалы, назначения администраторов, общие аккаунты | Управление сетью | Отказ | Отказ |
| Реестр/контакты, группы/состав, тренеры | Сеть | Свои филиалы | Отказ |
| Календарь, группы календаря, правила расписания | Сеть | Свои филиалы | Только назначенные группы/правила и фактические занятия |
| Создание/изменение расписания и занятия, отмена/замена | Сеть | Свои филиалы | Отказ |
| Тренерский журнал, открытие/отметка/завершение | Через фактическое назначение trainer | Через фактическое назначение trainer | Только свои фактические занятия и живая роль trainer |
| Административный журнал, история отметки, коррекция закрытого | Сеть | Свои филиалы, одна запись с причиной | Отказ |
| Общая история операций | Сеть | Свои филиалы | Отказ |
| Статистика сети | Разрешено | Отказ | Отказ |

Тренерский endpoint требует роли trainer и совпадения фактического тренера
сеанса; owner/administrator сами по себе эту проверку не обходят. Для этих
сотрудников реализован административный журнал. Матрица проверяет существующий
контракт V1-09/V1-11, отдельного изменения прав в этой QA-задаче нет.

Проверяется:

- Положительная и отрицательная матрица чтения обоих филиалов, отсутствие секретов
  и чужих контактов, `Cache-Control: no-store` на успешных ответах и отказах.
- Поиск реестра по чужому имени/контакту, локальный `hasMore` при более чем странице
  чужих карточек, фильтрация групп/сеансов/правил по назначению тренера.
- Фильтры действий и все страницы аудита; чужой филиал и сетевые события недоступны
  администратору. Raw payload, контакты, пароли и хеши не выдаются.
- Одинаковые статус и JSON ошибки для чужого существующего и отсутствующего ID:
  карточка, состав, сеанс, запись истории, фильтры группы/журнала.
- Запрещённые команды с корректными телами для реестра, групп/интервалов,
  расписания/предпросмотра, занятий и аккаунтов; подмена club/group/member/interval/
  rule/session/record/trainer ID, попытки присвоить роли и передать actor ID.
- Полный fingerprint 12 таблиц, включая роли, серверные сессии, версии и аудит,
  до/после отказов: запрещённые операции не оставляют частичных изменений.
- Общая идентичность участника нескольких филиалов меняется владельцем;
  администратор меняет только локальный контакт. Общий аккаунт тренера защищён
  от локального изменения логина/пароля/отключения.
- Тренер не меняет закрытый журнал; после замены прежний тренер сразу теряет
  чтение/запись/завершение, новый сохраняет отметку с правильным автором.
- Отзыв роли без нового входа, сохранение доступа ко второму филиалу, снятие
  administrator при оставшейся trainer, отключение всех ролей, повторное включение
  и replay старых cookie после logout.
- Разрешённое создание тренера/группы/участника с начальным включением,
  предпросмотр/сохранение расписания, разовое занятие/отмена и коррекция для
  владельца, каждого локального администратора, администратора обоих филиалов и
  смешанной роли в административном филиале.

## Запуск и результат

Нужны Go из `backend/go.mod`, тестовая PostgreSQL 18.6 и право `CREATE DATABASE`.
Не указывать рабочую БД или реальные пароли. Без `TEST_DATABASE_URL` интеграционные
тесты явно пропускаются; такой запуск не подтверждает матрицу.

```sh
cd backend
TEST_DATABASE_URL='postgres://test:test-only@127.0.0.1:5432/test?sslmode=disable' \
  go test -race ./tests/integration/access
TEST_DATABASE_URL='postgres://test:test-only@127.0.0.1:5432/test?sslmode=disable' \
  go test -race ./...
go vet ./...
go build ./cmd/server ./cmd/migrate ./cmd/create-owner
```

CI `.github/workflows/build.yml`, job `check`, уже задаёт `TEST_DATABASE_URL` и
запускает `go test -race ./...`; новый пакет автоматически включён в обязательный
прогон на настоящем PostgreSQL. Отдельного pipeline или новых миграций нет.

Локально прошли полный PostgreSQL18.6/Go1.27.2 `-race` suite, vet, форматирование,
сборка трёх Go-команд и TypeScript/Vite production build. В покрытых сценариях
нарушений доступа не обнаружено; production handlers не изменены. Итоговые
коммит/PR/CI и доставка в main записываются в live issue.

Гонки предметных операций и независимая сверка статистики — V1-15/#163.
Браузеры/физические устройства/HTTPS/PWA — V1-16/#164 и V1-17/#165; эта проверка
API не подтверждает их приёмку. Финансы и медицинские сущности не включены.
