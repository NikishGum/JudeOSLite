# Фоновое обновление без сброса экрана

Прямое поручение заказчика20.10.2026: устранить периодическое видимое обновление
страницы и опубликовать исправление. Это отдельное исправление текущего runtime,
не изменение экранов занятий/групп или состава функций.

## Подтверждённые причины

- `useReadBlock` и `useAttendanceReport` включали номер попытки в ключ данных.
  Каждые30секунд, при фокусе/возврате во вкладку и событии посещаемости предыдущие
  данные исчезали ещё до ответа API. Карточки, отчёт и последние изменения
  размонтировались, появлялись загрузчики, сбрасывались раскрытые блоки.
- `AuditHistory` обнулял страницу при каждом таком запросе.
- Ошибка фонового `/api/auth/me`, включая временную503/обрыв сети, удаляла сессию
  из состояния, CSRF и весь рабочий экран с черновиками.
- Колокольчик уведомлений имел второй30-секундный таймер поверх `useResource`.
  Фокус и visibilitychange также могли запускать дублирующие запросы.

PWA проверен по `PwaStatus` и `service-worker.js`: полная перезагрузка разрешена
обработчиком кнопки «Обновить приложение». Автоматического reload по таймеру нет.

## Исправление

Данные главной/отчёта привязаны к пути API/выбранным фильтрам. Номер попытки
запускает запрос, но не меняет область данных. Фоновая проверка сохраняет
содержимое и раскрытые элементы; успешный ответ обновляет значения на месте.
Смена фильтров/филиала по-прежнему сразу скрывает прежнюю область. AbortController
и проверки поколения продолжают исключать запоздалые ответы.

Временные ошибки сохраняют полученные данные и показывают ошибку. Отказы доступа
401/403/404/410 очищают соответствующий блок;401 по-прежнему завершает сессию.
Фоновая ошибка проверки сессии сохраняет рабочее состояние и CSRF до фактического
отказа сервера. Неизменившийся ответ сессии не обновляет корневой React-state;
порядок одинаковых ролей больше не меняет ключ рабочего экрана.

Сохраняются30-секундная проверка прав/данных и обновление при возврате во вкладку.
У уведомлений один таймер. Проверки сессии и `useResource` объединяют одновременные
focus/visibility запросы; явная смена пути/refresh отменяет прежнее чтение.

## Проверки

`frontend/e2e/background_refresh.py` использует синтетический API и управляемые
часы браузера. Исходная production-сборка воспроизвела ошибку после первого
30-секундного интервала: `Background read unmounted existing content`.

Исправленная сборка проверяется на1440и390px: задержанные ответы таймера,
фокус/visibility, явное обновление, новые значения счётчика, сохранение DOM,
фокуса/прокрутки/раскрытых блоков, временные503, очистка старого периода,
черновик семьи и его сохранение с CSRF, отзыв доступа и истечение сессии.
Также проверяются контраст и отсутствие горизонтального переполнения.

Локально: TypeScript/Vite production build, новый сценарий Chromium и22группы
существующих frontend-контрактов `screenshot_redesign.py` прошли, в том числе
повторно после включения актуального main с экранами занятий и групп.

CI запускает новый сценарий в Chromium/WebKit после существующих контрактов,
наряду с прежними Go/PostgreSQL, браузерными backend, PWA и deploy-проверками.
Синтетические ответы нового теста не подменяют эти backend-проверки. Публикация
выполняется штатным `Deploy test` после успешного CI текущего main.

Локальные команды:

```sh
npm --prefix frontend run build
npm --prefix frontend run preview -- --host 127.0.0.1 --port 4173
CHROMIUM_PATH=/usr/bin/chromium python3 frontend/e2e/background_refresh.py
CHROMIUM_PATH=/usr/bin/chromium python3 frontend/e2e/screenshot_redesign.py
PWA_BROWSER=webkit python3 frontend/e2e/background_refresh.py
```
