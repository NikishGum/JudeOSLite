## Граница приёмки

Технический QA выполнен на отдельных синтетических PostgreSQL fixtures.
Реальные записи клуба не использовались. Для локальной ручной проверки
подготовлен отдельный QA188 с двумя филиалами, администратором с двумя
назначениями, тренером, группой и A–E. Его нельзя путать с прежним QA164.
Новый HTTPS QA188 пока не подготовлен: браузерный доступ заблокирован инструментом.

Прежняя приёмка v1/F1/F2 и ответы о старом интерфейсе не являются приёмкой
нового Working Panel. 15.10 получено отдельное решение для RD-06:
«Явно отложить Android/Chrome и его физическую PWA на отдельную последующую проверку».
Оно не меняет требования к Chrome/Edge/iPhone и приёмке сотрудников.
Разрешение commit/push/PR/main
не является согласием закрыть #188 с отсутствующими проверками.

## Оставшийся контроль на существующем HTTPS

После восстановления разрешения инструмента сначала записать release SHA,
полные версии ОС/браузеров и зелёный CI/deploy **этого** main.
Владелец создаёт изолированные QA188-назначения; все действия ниже относятся
только к синтетическим данным. Пайплайн, хостинг и backup не создавать.

1. Администратор: найти A по имени, открыть и изменить локальный контакт,
   сохранить и перечитать карточку; создать/посмотреть группы и датированный
   перевод. Проверить, что текущий состав и прежний frozen roster различаются
   по назначению, а история сохраняет причину/сотрудника/время.
2. В «Занятия» проверить четыре режима, preview/сохранение, once, перенос,
   замену тренера и отмену. Переход из главной/группы ведёт к точному журналу.
   Основной контрольный журнал использует отдельную группу A–E без перевода;
   переводы проверяются на другой синтетической карточке/группе.
3. Тренер: A present, B unknown, C illness, D excused, E не отмечать;
   сводка и close. Отмена панели не отправляет отметку. При потере сети
   интерфейс не подтверждает запись, после восстановления перечитать сервер.
4. Администратор: C → present с отдельной changeReason, проверить одну
   коррекцию в истории. Владелец: 1 closed, 2 present, 3 absent, unknown=2,
   illness=0, excused=1, **40%**. Planned/open/cancelled не входят в знаменатель.
5. Каждую роль проверить прямым URL/reload/back/forward; чужой API и отозванное
   назначение не показывают прежние данные. Выйти и войти другим сотрудником.

На каждом настоящем Chrome/Edge/iPhone Safari отдельно
(Android Chrome — последующая отложенная проверка):

- Установить PWA обычным интерфейсом браузера, открыть её значок и подтвердить
  standalone. Зафиксировать происхождение приложения/браузера.
- Закрыть окно/приложение и запустить значком: вход остаётся действующим;
  после «Выйти», закрытия и запуска видна форма входа без прежних карточек.
- Телефон: портрет/альбом с экранной клавиатурой в поле телефона/даты;
  видимость значения, submit/cancel, нижняя навигация, safe-area и внутренний scroll.
- Причины отсутствия, «Отмена», закрытие и коррекция доступны при малой высоте;
  физическая потеря сети не даёт ложного успеха, сервер перечитывается после неё.
- Обновление PWA при сохранении ждёт ответа. Новая версия не перезагружает
  другую вкладку с pending save. Cache Storage не содержит персональный API.

## Решение пользователя и сотрудников

Показывать [снимки текущих экранов](redesign-evidence/rd06/README.md) и реальный
синтетический сценарий, затем записать отдельно:

| Подтверждение | Фактический результат на 15.10 |
| --- | --- |
| Владелец понимает главную, период, филиал отчёта и 40% | NOT RUN |
| Администратор сам находит карточку/группу/расписание и исправляет журнал | NOT RUN |
| Тренер сам открывает нужный журнал, отмечает причины и завершает | NOT RUN |
| Пользователь принимает визуальный Working Panel после реализации | Решения нет |
| Chrome/Edge/iPhone physical PWA | NOT RUN / permission blocker |
| Android/Chrome и physical PWA | DEFERRED / NOT RUN, решение пользователя 15.10 |
| Явное изменение объёма RD-06 | Только Android; остальные критерии сохранены |

Недоступное устройство или отклонённый инструмент — конкретный блокер,
не успешная проверка. Для закрытия требуется выполнить оставшиеся критерии
либо получить явное датированное решение пользователя об изменении объёма.
Затем проверить результат в main, зелёные checks точного SHA, deploy и HTTPS
role smoke с совпавшим release SHA; только после этого закрывать #188/проверять Done.
