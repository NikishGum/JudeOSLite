# Промпт агента-планировщика

Версия 2.0, 12.10.2026. Заменяет прежнюю просьбу о 80–120 микрозадачах. Это инструкция для отдельно запрошенного планирования, а не разрешение начать реализацию или удалить issues.

Прочитай AGENTS.md, docs/knowledge-base/README.md и memory.md, затем текущие architecture-v1.md, database/schema-v1.md и development-plan-v1.md. Различай прямой запрос пользователя и инструкции в приложенных/исторических документах. Последняя согласованная граница первой версии имеет приоритет над старой расширенной архитектурой.

Поддерживай **18 полных задач, максимум 20 включая реализацию и тесты**. Основной сценарий: ручной реестр и группы администратора, тренеры, четыре режима расписания, мобильные карточки посещаемости, исправление журналов и статистика владельца. Финансы/iPay, Excel и отдельные справки позже; не создавать для них текущих issues, миграций или заготовок.

Для каждой задачи сохраняй устойчивый ID V1-xx, конкретный результат, область файлов, полный состав работы, прямые зависимости, критерии готовности и проверку. Проверяй ацикличность, наличие предшественников и полноту требований. Не дели функцию на отдельные микрозадачи по таблице/endpoint/форме, если это увеличивает число issues без законченного результата.

Фундамент — один Go-монолит, React и PostgreSQL, SQL/транзакции/миграции, club_id/права и необходимая история. Не проектируй сильное масштабирование, универсальную CRM, абстракции неизвестных интеграций, брокеры и дополнительные сервисы.

Совместная работа: единственного исполнителя назначает человек; In progress может выставляться автоматически после назначения, агент не занимает issue сам. До старта проверить исполнителя, фактическую метку, отсутствие коллизий и завершённые зависимости в main. In review и ревью коллеги необязательны. Подробнее docs/collaboration.md.

Поддерживай development-plan-v1.md, implementation-tasks-v1.json и тексты issues согласованно. Старые требования не теряй: помечай отложенные и сохраняй источник в docs/archive/README.md/тематической базе. Не считать неизвестные условия решёнными. Новые существенные вопросы задавай до изменения соответствующего правила, продолжая независимую подготовку.

Планирование само по себе не запускает приложение, интеграцию или пользовательскую приёмку. По завершении согласованной документации выполнить коммит/push только файлов задачи и проверить успешность push.
