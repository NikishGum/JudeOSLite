## Данные, валидация и доступ

0003 расширяет существующие clubs/staff_users из 0002 полем version и создаёт audit_events. Применённые миграции не меняются; существующие ID, архив, хеши паролей, назначения и сессии сохраняются. Таблицы занятий здесь не создаются.

Все handlers проходят auth.Require: живая сессия/аккаунт и Origin/CSRF для изменений. Только owner читает общие списки и меняет филиалы/аккаунты. Администратор/тренер читает метаданные назначенного филиала; чужой, отсутствующий и некорректный ID дают одинаковый 404. Администратор не создаёт admin/owner и не меняет даже свой общий аккаунт. Новый аккаунт всегда administrator; JSON с role/isOwner или неизвестными полями отвергается. Эти API не редактируют/отключают owner; bootstrap остаётся отдельной командой.

Логин нормализуется по auth; занятый — 409 login_taken без присоединения чужого аккаунта. Название/имя 1–200 символов, адрес до 500, зона проверяется time.LoadLocation (Local запрещён, IANA включена в бинарник). Пароль 12–128 байт, Argon2id из auth; не возвращается клиенту. Передавать сотруднику лично/по защищённому каналу. Поле пароля очищается после попытки запроса; публичной регистрации/отправки паролей нет.

Редактирование заменяет только administrator-назначения, trainer-роли сохраняются. Пустой clubIds отзывает все назначения администратора. Создание требует минимум один действующий филиал. Назначение архивного филиала можно сохранить/отозвать, новое назначение туда запрещено. Disable действует на весь аккаунт; trigger 0002 отзывает сессии, повторное включение требует нового входа. Отзыв роли действует на следующий API-запрос без повторного входа.

## API

| Запрос | Контракт |
| --- | --- |
| GET /api/clubs | Owner: все филиалы, включая архив; [{id,name,address,timezone,archived,version}] |
| POST /api/clubs | Owner: {name,address?,timezone}; 201 с созданным филиалом |
| GET /api/clubs/{id} | Текущий доступ к филиалу, включая архивные метаданные; 200 |
| PUT /api/clubs/{id} | Owner: {name,address?,timezone,version}; 200 с новой version |
| POST /api/clubs/{id}/archive | Owner: {version}; сохраняет историю/назначения; 200 |
| GET /api/staff | Owner: текущие/бывшие staff без owner и parent-only, включая отключённые/без назначений; [{id,login,displayName,disabled,clubIds,version}]. clubIds — только administrator |
| POST /api/staff | Owner: {login,displayName,password,clubIds}; 201 с аккаунтом без пароля |
| PUT /api/staff/{id} | Owner: {displayName,disabled,clubIds,version}; общие данные и назначения атомарно, 200 |

Ответы no-store. Неверные поля — 400 invalid_input, конфликт версии — 409 version_conflict, новое назначение в архив — 409 club_archived, нет owner — 403 forbidden, недоступная БД — безопасный 503. Формы сохраняют ввод при ошибке, двойное нажатие блокируется. При конфликте список обновляется: закрыть форму и открыть актуальную запись. Успешная запись обновляет рабочий выбор. Архивирование требует отдельного подтверждения с объяснением последствий; восстановление/удаление филиала через UI/API этой задачи не предусмотрено.

## Транзакции, архив и аудит

Запись блокирует строку, проверяет version, обновляет updated_at/version и пишет audit_events в той же транзакции. Ошибка аудита откатывает изменение. Owner повторно проверяется/блокируется внутри транзакции. Назначение блокирует филиалы FOR SHARE в порядке ID, архивирование — FOR UPDATE.

`clubs.RequireActive(ctx, tx, clubID)` — обязательная проверка жизненного цикла для следующих предметных операций после auth.RequireClub. Она берёт FOR SHARE до конца транзакции и возвращает ErrArchived. V1-07/V1-08 обязаны вызывать её внутри создания/генерации будущих занятий. API занятий появляется в этих задачах; проверка не заменяет права. Историческое чтение разрешено, новые операции запрещены. Архивирование не удаляет/отменяет существующие занятия автоматически.

Audit хранит actor/entity/action/time, версии, название/зону/архив филиала, before/after administrator-ID филиалов и disabled, признаки изменения адреса/имени сотрудника. Без паролей/хешей/токенов, логинов/ФИО сотрудников и контактного payload/адреса. Отзыв не удаляет сотрудника, филиал или аудит; будущие исторические FK на автора сохраняются.
